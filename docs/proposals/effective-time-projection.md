# 结果视图中的有效时间投影

[主设计](../design/design-v1.2.md)区分事件时间和入库时间；原始记录只追加。本提案不改变这个约定。建议为结果视图提供显式的显示时间：对于经核实存在时间偏差的一组录音和转写，按同一个有界偏移显示开始和结束时间。未启用、未选中或没有读取权限的记录不因投影而改变其可见性或原始时间。

## 本提交可评审的范围

- 只有可信 API 宿主能在构造应用时显式注入投影；默认和常规 CLI 不启用。不提供自动发现、配置文件读取、请求参数、迁移或重写工具。作用范围以类型和记录 ID 明确给定；不按日期、来源或文本猜测范围。部署方若考虑启用，应独立核实范围与偏移，并记录启用及撤回依据。
- `/v1/source-timeline` 与 `/v1/recording-intervals` 按有效时间做半开区间匹配和排序；保持时长、ID、正文和授权不变。列表游标只用于同一实例、调用主体、查询和视图，并不授予读权限；仍是实时尽力读取，不承诺跨页快照。扫描有界，可能返回带后续游标的空页。
- `/v1/week-coverage` 与上述视图使用同一录音/转写投影。① 在既有授权下用存储时间计算有效范围，只返回原有占用格；活动红轨、聊天事件和权限状态不变。若①不支持投影，受影响的查询报不可用，不退回到错误的未校正格，也不通过 API 拉取记录正文重算。外部请求者不能提交偏移或修改范围；内部覆盖接口只接受可信 `api` 模块提交投影。
- `/v1/records`（含详情、历史）、活动、笔记、短语检索（含 MCP 转写查找）继续使用原有事件时间。④ worker 的选择、前置检查、提取和进度不读取此投影；既有活动或产物不会随显示时间移动或重算。

## 采纳前仍需决定

是否应在界面明确标记有效时间与原始事件时间；是否需要独立的、可审计且可撤回的授权与修订模型；是否将同一时间基准用于短语搜索、活动、worker 和历史重判。若将来扩展到这些路径，须先明确所有权、时窗/游标兼容性、进度与依赖处理、旧结果和隐私边界，由相应负责人审核后另行同步设计与契约。只接受文档时，可保留本提案而不接线；不应以临时部署行为代替采纳。
