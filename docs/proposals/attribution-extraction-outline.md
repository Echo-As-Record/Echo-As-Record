## 3. ③ 归属

目标是回答“这段话是谁说的、在哪儿”，尤其是“是不是用户本人”。④ 判断重要性需要这个答案。

保持不变：raw 只追加；用户纠正或确认的归属不被自动重判推翻；一条 raw 至多是一个对象的参考；所有写入经 ①；完成用 FinishReevaluation。

### 3.1 #16 代码的问题（读 5200899 源码）

1. `matching.py` 取最高相似度，过阈值就归，不比第一、第二名的分差。旧 Ear 实测中，用户本人的声音被自己的匿名分身抢走，分差只有 0.01–0.04（旧系统要求 0.08）。**PR #35 已改。**
2. 每个匹配不上的声纹都新建一个人物，不看 `sample_quality`，短而差的声音也会变成“人”。
3. 每次匹配都读取并登记全部人物为依赖。N 个人物、M 条声纹就是 N×M 条依赖。
4. 没有“哪个人物是用户本人”的标记。
5. 缺 `reattribute_range`、初始补扫、空人物清理、合并人物。

### 3.2 离线评估的发现（聚合数字，数据在仓库外）

- 线上约 4150 条声纹，模型与旧库相同（ECAPA，192 维）。
- 模拟线上匹配：约 4150 条声纹建出约 3800 个未命名人物，问题 2 在真实数据上非常严重。
- 本人声音对本人参考的相似度中位数约 0.44，说明同一个人在不同场景下差异很大，单一阈值难以兼顾。
- 未知声音粗分档（余弦 ≥0.5 算“见过”，规则宽松）：路人约 18%，常出现约 72%，其余约 10%。“常出现”比例偏高，可能是模型把不同的人认成相似，要等核对表 B 组的标注才能判断。
- 旧库的已绑定归属是旧系统自动分配的，用来评估会循环论证，不能当真值。

### 3.3 设计要点

- **A. 匹配**（PR #35 已实现）：过阈值且分差够才归；按人汇总参考得分（最高或前 k 平均）；阈值和分差写配置，不写死。
- **B. ★未知人物**：匹配不上的声纹不建新人物，归全局唯一的“未知人物”，做法类似未知地点：没有参考，不参与匹配。设计 §6.1 现写“匹配失败新建未命名人物”，需改。已并入 PR #28 的提案。
- **C. ★候选有界**：已命名或用户确认过的人物总是候选；未命名人物只在同一录音和最近时间窗内参与匹配。依赖只登记真正参与比较的候选，依赖量从 N×M 变成有界。
- **D. ★合并人物**：分身不能只靠算法消除，见 [person-merge-mvp](person-merge-mvp.md)。
- **E. ★`person.is_self`**：标记用户本人，至多一个。PR #28 的提案改为由系统维护的本人样本库加 `is_self`。目前没有单独的提案。
- **F. `reattribute_range`**：分批执行，记录进度，可续跑，跳过受保护的归属；初始补扫用同一套逻辑。
- **G. 空人物**：参考和归属都没有时整体替代；还有归属时保留，并给出提示数据。
- **不做**：改 ASR；环境声与内容的多维归属；自动合并建议。
- **以后可做**：旧 Ear 有一套用 LLM 看上下文给说话人提建议的代码，但从未上线。新 ③ 没有这部分；人物记忆（`services/habit`）里有基于称呼的候选。建议只给候选，不直接改归属。

### 3.4 建议的步骤与验收

1. 人工标注核对表，判断 ECAPA 够不够用（建议标准：B 组 AUC ≥0.95 且 A 组 AUC ≥0.90）。不够用就对比 CAM++。
2. 审核 PR #35；合入时同步线上配置。
3. 决定是否采纳 PR #28 的提案，决定未知人物、本人样本库、30 天保留的做法。
4. 实现 C、F、G 和依赖有界，并用合成数据（数千条声纹）做规模测试，记录依赖数和吞吐。
5. B、D、E 在提案通过后实现。
6. 在隔离的 ① 上用真实数据跑一天，验收：
   - 每条声纹和每个 GPS 点恰好有一条归属；
   - 重跑新增 0 条；
   - 用户确认过的归属不变；
   - 本人召回和误认率达到负责人定的线。

## 4. ④ 活动提取

方向已经在 #27 的提案中展开，这里只记录要点和来历：

- **重要性不放进 activity**：C07 规定活动划分和名称描述不读归属，而判断重要性要知道“是不是用户本人在说”。改为由 ④ 单写一份按活动的评估记录，归属一改，经 ⑤ 只重判评估，不重划活动。见[评估骨架](activity-assessment.md)。
- **重要性的定义**沿用旧分诊：high 指“用户本人在口述想法、计划或决定”，不是一般意义的重要程度。
- **④ 只给重要性，不发推送**：推不推送由送达方按“high、未迟到、每日上限、同一件事只推一次”决定。
- **ASR 纠错不放进 ②**：转写是只追加的 raw，入库时让模型改写，错改就无法复原。② 只加确定性质量标记；纠错做成独立派生层，见[转写纠错](transcript-correction.md)。旧分诊停用前，新纠错在同一批录音上的效果要不差于旧分诊。
- **结果审核**：⑦ 只校验 JSON 结构，不校验内容。先做确定性检查，再对 high 和会触发动作的结果做一次独立复核，见[结果审核](extraction-result-audit.md)。
