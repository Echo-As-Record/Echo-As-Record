# 提案：④ 结果的确定性审核与独立复核

> **状态：proposed，未采纳。** 本文提议在④写入活动、产物、建议之前增加确定性审核，并对少数高价值结果做一次独立模型复核。确定性审核只拒绝明确不成立的输出，不改变已采纳的产品语义，大部分属于实现层面的加固；但“结果按条目引用证据并建立索引”“复核结果怎样影响下游”属于行为变化，需负责人决定。除第 3.4 节的人名检查外不依赖③。

## 1. 问题

- ⑦只校验输出是否符合 JSON schema，不看内容。
- ④现有检查只有三项：活动时间在提取范围内（`activity_out_of_range`）、活动引用的证据 id 在输入里（`unknown_evidence_reference`）、产物引用的证据 id 是输入的子集。
- 模型可能编造原话、引用与活动时间无关的证据，或者在没有依据的情况下写出人名。这些错误现在会直接写入，并可能变成外部动作建议或推送。

## 2. 两层审核

1. **确定性审核**：对全部结果，在业务提交之前执行，只用输入里已有的数据，不调用模型。
2. **独立复核**：只对 `importance=high` 的评估结果（[评估提案](activity-assessment.md)）和会生成外部动作建议的产物做一次额外的模型调用。其余结果不复核。

## 3. 确定性审核的检查项

### 3.1 证据 id 存在

结果里引用的每个证据 id 都必须是本次调用输入里实际给出的原始记录（现有检查），且按①的当前状态仍然有效。

### 3.2 时间在范围内

- 活动的 `[start, end)` 在本次提取范围内（现有检查）。
- **新增**：活动和产物引用的每条证据，时间都要与所属活动的时间区间重叠；不能引用活动之外的录音来支撑这个活动。
- **新增**：动作建议里的日期必须是合法时间；“从证据推出”的部分仍由提示词约束，本层不判断语义。

### 3.3 结果可索引；引用的原话能在转写里找到

模型**不输出原话**（YijieYing 2026-11-25）。原话一律由④从转写里取，模型只负责指出依据在哪条证据。

- **按条目引用证据**：生成调用的输出改为条目列表，每个条目是一段 Markdown（段落、列表项、动作说明、评估理由）加它依据的证据 id。④把条目拼成 `body_md`，并保存“条目在正文中的位置 → 证据 id”的索引（暂名 `evidence_index`）。整份结果的 `evidence_ids` 是各条目证据的并集，与现有字段一致。
- **双向可查**：从结果的任一条目能查到它依据的转写；从一条转写能查到引用了它的活动、产物、建议和评估。后者由①现有的依赖记录支持，不另建表。
- **需要原话时由④取**：⑥展示、推送摘要等需要原话时，按索引取对应转写原文（有纠错时附上纠错），不使用模型写出的文字冒充原话。
- **正文里的引号文字要核对**：正文条目中加引号的文字，必须能在该条目所引证据的转写原文里找到。比较前只做固定的归一化：统一全角半角、合并空白、去掉首尾标点；不做模糊匹配。有纠错记录时（见[纠错提案](transcript-correction.md)），也接受在“原文按纠错替换后”的文本里找到。找不到即不通过。
- 没有证据 id 的条目不通过；纯格式条目（例如标题）可以不带证据，由输出 schema 区分。

### 3.4 没引用的归属不出现人名

- 结果里出现的人名，必须满足下面之一：
  - 出现在所引用证据的转写原文或纠错里（C07 允许使用原始转写里本来出现的名字）；
  - 来自本次输入里给出、且被结果引用的归属所对应的人物 `name`。
- 判断“哪些字符串是人名”用已知名单：用户词表中 `category=person` 的词条，以及③的人物名字。
- **分阶段**：③就绪前只用词表名单，不读③；③的人物名字加入名单后，这项检查对人物名字字段登记依赖。活动划分和名称描述的审核即使读名单，也只用于拒绝输出，名单内容不进入模型输入，不改变 C07。

### 3.5 未通过时

- 任一项不通过，整次输出视为已知非法输出，不提交部分结果。
- 重判请求按现有协议以 failed 完成；定时和手动提取的运行记为失败并记录不通过的检查项和涉及的 id，不记录正文。
- 是否允许一次“带错误说明的修复调用”（新的 call_id，计入调用上限）见第 6 节待决。不在原 call_id 上重试。

## 4. 独立复核

- **范围**：`importance=high` 的评估结果；会生成外部动作建议（日历、提醒事项）的产物。普通产物、`normal`/`low` 的评估不复核。
- **独立**：单独一次⑦调用，`purpose` 为 `extraction_review`；输入只有待核对的结论和它引用的证据原文（含纠错），不带原调用的提示词、推理或其他候选。可以使用与原调用不同的模型别名。
- **输出**：`verdict` 取 `supported` / `unsupported` / `uncertain`，加一句理由，引用的证据 id 仍过一遍第 3 节的检查。
- **结果怎样用（建议）**：
  - 复核结论和复核调用 id 写进被复核的记录，作为它的一个字段，不单设类型。
  - 外部动作建议本来就要用户审核（[设计 §7.6](../design/design-v1.2.md)）；复核结论只作为提示给审核人，`unsupported` 不自动删除建议。
  - 评估结果为 `high` 而复核不是 `supported` 时，记录保留模型给的 `high` 和复核结论；下游（推送方）只把 `high` 且 `supported` 当作可推送。④不自行把 `high` 改成 `normal`。
  - 复核调用本身失败或结果未知时，视为没有复核通过，不阻塞记录写入。
- 复核登记的依赖与被复核记录相同；被复核记录重判时复核一起重做。

## 5. 影响

- **④**：提交前的审核步骤；生成调用改为按条目输出并保存 `evidence_index`；复核调用。
- **⑦**：无改动，多一种 `purpose`。
- **契约**：产物与评估记录增加可选字段 `evidence_index`、`review`，只增不改义。
- **③**：第 3.4 节在③就绪后读人物名字，只读。

## 6. 验收（合成数据）

1. 引用输入外的证据 id、活动区间外的证据、正文中编造的引号文字、未依据的人名、缺证据的条目，各自被拒绝，不写入部分结果。
2. 引号文字在原文中逐字存在、或只在纠错后存在，都能通过；从条目能查到证据，从证据能查到条目。
3. 归一化只处理固定的几类差异；改一个字的“近似原话”不通过。
4. `high` 评估和动作类产物各发一次复核调用，其他结果不发；复核失败不阻塞写入，只标记为未复核。
5. 重判时审核规则相同，结果不变时不新增版本。
