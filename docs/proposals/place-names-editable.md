# 提案：地点名字可编辑、可有多个名字

> **状态：proposed，未采纳。** 本文涉及[GPS 逆地理编码提案](gps-reverse-geocoding.md)第 4 条“④不得把地名当作③的 `place`”与 [C07](../decisions/mvp-confirmed-decisions.md) 的边界，以及第 6.4 节“用地名给新建地点提供默认名字”属【以后】的范围，需要负责人明确决定。新增字段属于契约增补，采纳后仍需①负责人与 I 审核。

## 1. 需求

1. 地图服务给出的地名常常不是用户口中的名字。例如楼宇会被标成“XX 大厦”或干脆没有楼名，用户自己叫它“C 楼”。用户要能改。
2. 同一个地方常有几个叫法（正式名、简称、口头叫法），都应当认作同一个地点。

## 2. 现状

- `gps_geocode`（#17）是**原始数据**：只由坐标和一次地图查询决定，只追加、不能改。它直接进入④划分活动和写名称描述的输入。
- ③的 `place` 是语义对象，用户手动创建、命名，有版本。PR #16 支持 `create_place` 和 `rename`，名字只有一个 `name` 字段。
- 产物生成时可以读③的人物地点字段并登记依赖；改名会通过⑤触发依赖 `name` 的下游重判。活动划分和名称描述不读③（C07）。

所以“编辑地名”不能改 `gps_geocode`，只能落在③的 `place` 上；而 ④划分活动时只看得到地图地名，看不到用户改过的名字。

## 3. 做法

1. **用户的名字放在③的地点上，`gps_geocode` 不变。**
   - 地点增加 `aliases`（别名列表），与 `name` 并存：`name` 是首选名，写进产物；`aliases` 是其他叫法。
   - ③增加反馈命令：增删别名、把某个别名设为首选名。改名沿用现有 `rename`。

2. **从地图地名一步建地点。** 用户在时间线或地图上点一个带地名的 GPS 点，选“改名”时，③用这批 GPS 点新建地点（即现有 `create_place`），默认名字取 `gps_geocode` 的楼宇名或地址，用户当场改成自己的叫法。
   - 这把[逆地理编码提案](gps-reverse-geocoding.md)第 4 条里“以后”的“用地名提供默认名字”提前；仍是用户手动创建，不自动建地点。

3. **④的读取边界（需要负责人在下面两项里选）**
   - **选项 A（建议）**：活动划分和名称描述仍只读原始数据（地图地名），保持 C07 不变；产物和建议读③地点的 `name`、`aliases` 并登记字段依赖。用户改名后，产物里的名字经⑤更新，活动名称不自动变，用户可手动重新提取。
   - **选项 B**：允许④划分活动时也读用户给地点起的名字。用户的名字是本人写下的，不是推断，但地点归属本身是③推断的，这会让推断结果进入活动划分，直接改变 C07，不建议在 MVP 做。

4. **⑤的传播**
   - `name` 和 `aliases` 分别作为可依赖字段。改首选名触发依赖 `name` 的下游；只增删别名时，只触发实际读过 `aliases` 的下游。
   - 只依赖参考的归属不受名字变化影响，与第 6.3 节一致。

5. **别名的其他用途（不在本提案实现）**：别名可以作为[ASR 用户词表](asr-user-glossary.md)的来源，帮助④认出转写里口头提到的地点。两者是否打通在词表提案中另定。

## 4. 待决

1. 第 3.3 节选 A 还是 B。
2. 提前“用地名作默认名字”是否接受。
3. 人物是否也加 `aliases`。人物同样有多个叫法，可以一并做，也可以等需要时另提。
4. 别名数量和长度上限；同一别名能否属于两个地点（建议允许，地名本来就会重名）。

## 5. 不做

- 不修改 `gps_geocode`，也不让用户“纠正”地图服务的结果。
- 不自动建地点，不自动把地图地名当成地点名。
- 不合并地点：地点只能手动创建，重复时用户可把参考移到一个地点后删除另一个。

## 6. 影响与验收

- **③**：`aliases` 字段与别名反馈命令；从 GPS 点建地点时取默认名字。
- **⑥**：地点名字和别名的编辑入口；GPS 点上“改名”的入口。
- **④**：产物读取 `name`、`aliases` 并登记字段依赖；活动划分按第 3.3 节的选项。
- **⑤**：无新接口；按字段依赖传播。
- **①、契约**：`place` payload 增加 `aliases`，①负责人与 I 审核。

验收用合成数据：

1. 从带地名的 GPS 点建地点，默认名字取地图地名，用户可当场改。
2. 增删别名、切换首选名都追加地点新版本；`gps_geocode` 不变。
3. 改首选名后，依赖 `name` 的产物被重判、写出新名字；只改别名时，没有读过 `aliases` 的下游不被重判。
4. 选项 A 下，改名不改变已划分的活动及其名称。
