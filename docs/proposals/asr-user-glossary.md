# 提案：用户词表纠正常用词误识别

> **状态：proposed，未采纳。** 本文提议新增一个由用户维护的词表，让④在调用模型时据此纠正转写里的常见误识别。其中第 4 节涉及 [C07](../decisions/mvp-confirmed-decisions.md)“活动划分/名称描述只用原始数据”的边界，需要负责人明确决定。新增数据类型属于契约增补，采纳后仍按[工作分解](../design/work-breakdown-v1.2.md)第 11 条由①负责人与 I 审核。

## 1. 问题

旧 Ear 的语音识别会稳定地把一些常用词认错，例如项目名 “Ear” 被转成 “year”“夜”“EY”，人名、课程名、项目名也经常错成同音词。这些错词进入转写后：

- ④划分活动、写名称描述和生成产物时，模型看到的是错词，笔记和待办里会出现错的名字；
- 同一个词每次错法不同，检索和按人、按项目回看都对不上。

转写是原始数据，只追加、不修改；② 封装旧 Ear 的处理，不重写识别模型。所以纠正不能改转写本身，也不在新 Ear 的范围内重新训练识别。

## 2. 做法

1. **新增数据类型 `glossary_entry`**（暂拟名），一条记录是一个词条：

   | 字段 | 说明 |
   |---|---|
   | `canonical` | 正确写法，例如 `Ear` |
   | `variants` | 已知错写，例如 `["year", "夜", "EY"]`；可为空，只用于告诉模型这个词存在 |
   | `category` | `person` / `project` / `term` / `other`，只作提示 |
   | `note` | 可选说明，例如“项目名，读音同 ear” |

   词条由用户维护：⑥提供增改删入口，写 `feedback`；④消费反馈并写词条（与“规则”同属④单写，见第 5 节待决 1）。词条有固定 id，修改追加新版本，删除为整体替代。

2. **④在调用模型时附上相关词条**：只附 `canonical` 或任一 `variants` 出现在本次输入转写里的词条，加上数量有限的全局常用词条，避免整张表塞进提示。附上的词条要登记依赖（字段 `canonical`、`variants`）。

3. **纠正只发生在模型输出里**：转写原文不变；⑥展示转写时不做文字替换。这与[设计 v1.2](../design/design-v1.2.md) 第 3.2 节对人物地点名字的做法同一思路：名字写进生成结果，不靠显示层替换。

4. **词条变化的传播**：
   - 依赖了该词条的产物、外部动作建议，按现有依赖分析收到重判，按新词表重新生成；
   - 已划分的活动及其名称描述**不自动重划**（与第 7.1 节“改名不自动重划活动”一致），用户需要时手动重新提取。

## 3. 与现有设计的关系

- **不改变归属**：③不读词表；人物、地点的名字仍由用户命名。词表里的人名只帮模型认出转写里的错词，不建立“词条 → 人物”的对应。
- **基线**：PRTS 的录音分诊已在用人工维护的纠错表做同样的事，效果可用，本提案把它搬进 Ear 并纳入依赖管理。验收时用它做对照。

## 4. 需要负责人决定：活动划分能否读取词表

[C07](../decisions/mvp-confirmed-decisions.md) 规定活动划分、名称描述只用原始转写、时间、GPS、手机数据，不读取推断的人物地点。词表既不是原始数据，也不是推断结果，而是**用户直接写下的输入**。

- **选项 A（建议）**：允许④划分活动、写名称描述时读取词表。理由：错词最常出现在活动名称里，且词表来自用户本人，不存在“推断结果反过来影响划分”的问题。代价：词表改了，已有活动名称不会跟着改，需要手动重新提取。
- **选项 B**：只在生成产物和建议时读取词表，活动划分和名称保持只读原始数据。代价：活动名称里仍会出现错词。

[GPS 逆地理编码提案](gps-reverse-geocoding.md)的处理是把地名定为原始数据，这里不照搬：词表由用户随时修改，不能当原始数据。

## 5. 待决

1. 写入方：④单写（与规则一致，本文建议），还是新设由⑥直接写的用户配置类型。
2. 第 4 节选 A 还是 B。
3. 每次附上的词条数量上限，和“全局常用词条”的选法。
4. 初始词条是否支持从用户已有的纠错表批量导入（只在用户本机导入，不进仓库）。

## 6. 不做

- 不按用户声音微调识别模型、不做识别侧的热词或 embedding。这些属于旧 Ear 或识别模型一侧，需要的话另提。
- 不自动从转写里挖掘新词条；以后可以作为建议，由用户确认后加入。
- 不改转写原文，不在显示层替换文字。

## 7. 影响与验收

- **④**：消费词表反馈、写词条；调用模型时附上相关词条并登记依赖。
- **⑥**：词表的增改删入口。
- **①、契约**：登记新类型及其 payload schema，①负责人与 I 审核。
- **⑤**：无新接口，按已有依赖分析传播词条变化。

验收用合成数据：

1. 转写里含已知错词时，产物写出正确写法；不含时不附该词条。
2. 附上的词条都登记了依赖，未附上的没有登记。
3. 修改词条后，依赖它的产物被重新生成，活动划分不变。
4. 转写原文和⑥的转写展示不变。
5. 在经用户同意的一天真实数据上，与 PRTS 分诊纠错表的结果对照，错词残留数不高于对照基线。
