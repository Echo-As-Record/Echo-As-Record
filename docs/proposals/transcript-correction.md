# 提案：转写纠错派生层（`transcript_correction`）

> **状态：proposed，未采纳。** 本文提议新增④单写的语义类型 `transcript_correction`、给②的转写增加确定性质量标记，并对 [C07](../decisions/mvp-confirmed-decisions.md) 补一句修订。三者都改动已采纳设计或公共契约，需负责人明确决定；新增类型与字段采纳后仍按[工作分解](../design/work-breakdown-v1.2.md)第 11 条由①负责人与 I 审核。本文不依赖③，可先于③的匹配校准实施。

## 1. 问题与现状

- 旧 Ear 的识别会稳定地认错项目名、人名、课程名（例子见[词表提案](asr-user-glossary.md)第 1 节）。④划分活动、写名称描述、生成产物时，模型看到的是错词。
- 现在由仓库外的 PRTS pulse 做纠错：用 Codex 加人工词表，原文不改，纠错另存。312 段转写里 45 段有纠错，共 114 处。设计上 pulse 最终改读④的结果（R24），所以纠错要搬进 Ear。
- 转写是只追加的原始数据（[设计 §3.2](../design/design-v1.2.md)），不能改写；②只做确定性处理，不调用模型。

## 2. 提议

### 2.1 纠错是④写的派生记录，原文不变

新增语义类型 `transcript_correction`（暂名），④单写，经①保存，一条转写一份当前记录：

| 字段 | 说明 |
|---|---|
| `transcript_segment_id`、`transcript_segment_version` | 被纠正的原始转写 |
| `corrections` | 列表，可为空（空表示“检查过、没有要改的”）。每项见下 |
| `glossary_entries` | 本次调用附上的词条 id 与版本（与依赖登记一致） |
| `method` | 生成方式，例如提示词版本、模型别名；不存提示词正文 |

`corrections` 每项：

| 字段 | 说明 |
|---|---|
| `start`、`end` | 原文中的字符位置，半开区间，按 Unicode 码点计 |
| `original` | 原文片段，必须与 `text[start:end]` 逐字相同 |
| `suggested` | 建议写法，不能与 `original` 相同 |
| `basis` | `glossary`（附 `glossary_entry_id`）或 `context`（上下文推断，附一句理由） |

规则：

1. **原文不变。** 转写记录不改、不追加替换版本；⑥展示转写时以原文为主，纠错只作为旁注显示，不做替换。
2. **消费者读“原文 + 纠错”。** ④在划分、选规则、生成时把原文和纠错列表一起交给模型，由模型使用建议写法；不把替换后的文本当作新的原始数据。引用原话时引用原文（见[结果审核提案](extraction-result-audit.md)）。
3. **确定性校验后才写入。** `original` 对不上原文、位置越界或重叠、`basis=glossary` 却引用了未附上的词条，整条纠错结果视为非法输出，不写入。
4. **依赖。** 纠错记录依赖所纠正的转写版本和附上的词条（字段 `canonical`、`variants`）。转写只追加，实际会触发重判的只有词表变化：⑤请求重判后④按新词表重做，结果不变时不新增版本，仍提交完成记录。
5. **谁触发。** ④在一次提取开始、划分之前，对范围内还没有当前纠错记录的转写先做纠错，再进入划分。纠错调用经⑦，`purpose` 为 `transcript_correction`，按窗口批量发送，一次调用可以产出多条转写的记录。
6. **用词表。** 词表沿用[词表提案](asr-user-glossary.md)的 `glossary_entry` 及其附词规则（只附在本次转写里出现的词条和少量全局常用词），不另建词表。该提案仍是 proposed，且写入方未定；本提案依赖它先采纳，或至少先定写入方。
7. **人名只是文字。** 纠错里的人名是对转写文字的更正，不对应③的人物 id，不影响归属。

### 2.2 ② 只加确定性质量标记

②不改写、不删除转写，只在写入时附加确定性的质量标记（新增可选字段，暂名 `quality_flags`，值为枚举列表）：

| 标记 | 判定（阈值写配置） |
|---|---|
| `empty_text` | 去掉空白后为空 |
| `abnormal_repetition` | 同一短语连续重复超过阈值，常见于识别器“卡住” |
| `time_out_of_range` | 转写时间超出所属音频的起止 |
| `no_speech_detected` | 语音活动检测认为无人声，却有文字 |
| `degraded_recognition` | 由降级识别路径产出（例如主识别失败后的备用路径） |

标记只给下游参考：④可以把它们放进模型输入、跳过空文本，或在审核时降低这类证据的权重，但不能当成“这段话不存在”。已写入的转写不回填标记（原始数据只追加）；需要给旧数据补标记时另提，例如单独的 raw 类型引用转写 id。

### 2.3 C07 修订（需负责人决定）

在[设计 §7.1](../design/design-v1.2.md) 第 4 条后补一句：

> 活动划分、名称和描述还可以读取用户词表（`glossary_entry`）和转写纠错（`transcript_correction`）。二者分别是用户直接写下的输入和对原始转写的文字更正，不含人物、地点或归属推断；其中的名字只作文字使用，不猜人物地点 id。

配套约定：词表或纠错变化不自动重划活动，与“改名不自动重划”一致；活动名称描述记录读过哪些纠错版本作为追溯，但不登记会触发活动重判的依赖。`rule_selection`、产物、建议读纠错时照常登记字段依赖，按依赖分析重判。

这会让[词表提案](asr-user-glossary.md)第 4 节的选项 A 成立，二者应一起决定。

## 3. 为什么不放进②，也不改写原文

- 让模型在入库时改写，错改之后原文无法复原；声纹、时间、依赖、去重都以原始转写为固定来源，改写会让它们失去依据。
- ②按设计只做确定性处理；模型推断属于有所属模块、可重判的语义层。纠错写在④，与④使用它的场景放在一起，依赖和重判走现有机制。

## 4. 与 pulse 的过渡

- **pulse 不停**，直到④的纠错在同一批录音上不差于 pulse（YijieYing 11-22 决定）。
- 对照集：pulse 已处理的 312 段（45 段有纠错，共 114 处）。数据和结果留在仓库外（例如 `~/research/ear-eval`），仓库只放比较脚本和合成样例。
- 比较方式（建议，需用户定线）：以 pulse 的 114 处为参考，统计④的命中、漏改、多改；对两边不一致的地方抽样，由用户判对错。“不差于”指用户判定后的错改数和漏改数都不多于 pulse。
- 纠错提示词和词表从 pulse 搬过来作为起点；词表导入只在用户本机做。

## 5. 影响

- **④**：纠错步骤、纠错记录的写入与重判、消费“原文 + 纠错”；仅转写模式的调用上限（每次运行 5 次）要为纠错留出额度或单独计数。
- **②**：写入时计算 `quality_flags`。
- **①、契约**：登记 `transcript_correction`（semantic，writer `extraction`，可重判）；`transcript_segment` 增加可选字段 `quality_flags`。只增不改义。
- **⑥**：转写展示纠错旁注（可后做）。
- **⑤**：无新接口。
- **③**：不受影响，不读纠错。

## 6. 验收（合成数据）

1. 转写含词表中的错写时生成纠错，`original` 与原文逐字一致；不含时纠错列表为空，记录仍存在。
2. 非法纠错（位置越界、原文对不上、引用未附词条）被拒绝，不写入。
3. 转写原文和⑥的原文展示不变。
4. 改词条后，依赖它的纠错和下游产物被重判；活动划分不变。
5. 结果不变时不新增纠错版本，但有完成记录。
6. 质量标记只出现在新写入的转写上，旧转写不被改写。
7. 本机对照：在 312 段上按第 4 节的方式与 pulse 比较，结果由用户判定。
