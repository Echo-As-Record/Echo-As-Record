# Ear MVP 工作分解 v1.2

> 采纳依据：项目负责人已逐项确认本轮决定并明确授权同步文档，决策来源见[确认索引](../decisions/mvp-confirmed-decisions.md)。`accepted` 表示目标已采纳，不表示实现完成、契约冻结或本文件经过新一轮人工审核；本文件不复制旧版 review 字段。
> 本文以 [v1.1 历史工作分解](work-breakdown-v1.1.md) 为基础，保留未改变的业务，重新分解扩大后的 MVP；沿用负责人已明确承担①的分工，不新增其他人员任命；日期、工期和完成比例未确定，不沿用旧版粗估作为进度承诺。
> 行为定义见[设计 v1.2](design-v1.2.md)、[信号补充](signals-supplement.md)、[插件 MVP](plugins-mvp.md)；架构依据见[存储与运行模块 ADR](../adr/0001-storage-and-runtime-modules.md)。本文只分配职责、交付与验收，不另建一套字段契约。工程阶段细化见[实施计划](../../ai-docs/plans/mvp-implementation.md)。

## 0. 所有部分共同遵守的约定

1. **数据与版本**：原始数据只追加，版本固定为 1；语义信息、规则等修改追加同 id 的新版本。最大版本是当前版本，旧版本不可变并保留写入时的状态，旧 `active` 不等于当前。整体替代追加内容与 n 相同、状态为 `superseded` 的 n+1 终止版本，事件新旧版本为 n+1/n；之后拒写，重复替代不新增版本或事件。默认查询排除整体替代对象，按 id 和历史查询仍可读取。
2. **单写与身份**：每模块只写自己逻辑空间的业务数据，统一通过 ① SDK；身份来自可信凭据，不采信调用方自报模块名。数据所属模块就是重判执行方，登记一个所属方和是否支持重判，不另设第二执行人。登记中准确字段名仍待契约设计，不把此处中文概念映射成已实现字段。

   | 模块 | 单写职责 |
   |---|---|
   | ① | 公共依赖、事件、消费标记基础设施；插件登记、权限、管理操作结果系统记录 |
   | ② | 外部来源的原始数据 |
   | ③ | 人物、地点、参考、归属关系；自身重判结果系统记录 |
   | ④ | 活动、规则、`rule_selection`、md 产物、外部动作建议、提取记录；自身重判结果系统记录 |
   | ⑤ | 传播记录与调度追踪，不代写业务结果或插件登记 |
   | ⑥ | 用户反馈，包括经管理员验证的管理反馈及外部动作执行反馈 |
   | ⑦ | 经 ① 统一保存的大模型调用系统记录 |
   | 插件 | 获准命名空间内自己的业务结果；可重判插件还写自身重判结果系统记录 |

3. **反馈和事件**：用户操作先写反馈再异步处理，系统记录不发事件。总线仍只有「数据库被修改」和「请求重新判断」；前者仅 ① 发，后者仅 ⑤ 发。①不再是只发不收，而是仅消费归自己的管理反馈，不接管③④⑤业务；⑥不直接修改登记或权限。收到事件先查当前状态，重复投递幂等。
4. **输入与追溯**：保留统一输入格式、来源用户、适配器版本、去重键、大文件引用；id 为小写 UUIDv7，时间为 UTC。写入沿用触发它的 `root_feedback_id` 和 `depth`，系统根源为 `"system"`。大模型一律经⑦，重判调用还关联请求 id；多起因不得丢失根源，也不擅改已有根源字段含义。
5. **字段依赖与新鲜度**：`fields` 可选，缺省按全对象版本判断；选择 `payload` 顶层字段时比较登记版本与当前版本的完整字段 JSON 值。拒绝空数组，字段名去重排序；缺失不等于 null，数组顺序有意义；A→B→A 当前可不再过时，但已发请求不自动撤回；整体替代总是过时。接口中 `fields` 的准确位置待冻结。
6. **完整登记与原子提交**：声明强制依赖的类型，新建、更新及内容无变化的 Update 都同批提供完整依赖，未登记整批拒绝，不自动继承；显式空集表示确实无输入依赖，不等于缺登记。整体替代免新登记并保留历史。①验证存在、引用、新鲜度和权限，业务方保证登记真实完整；结果无变化时不新增业务版本、不发业务事件，但仍提交依赖刷新和完成记录。
7. **正文与规则**：md 产物为纯 Markdown，直接写名字，不存特殊人物/地点引用标记，也不由正文猜 id。活动划分及名称、描述仅用原始转写、时间、GPS、手机信息，不读取推断人物地点；原始转写中的名字可用。产物保留活动范围内所有归属关系的粗粒度依赖，加实际使用的人物、地点字段依赖。规则修改/删除本身不主动重算历史；其他输入触发历史重判时使用原规则当前版本，删除/整体替代和规则选择变化的处理见④。
8. **完成与失败**：③④及可重判插件各写自己的结果系统记录；成功结果与业务写入、依赖刷新、`MarkProcessed` 同批完成。无变化也要完成记录；崩溃未交结果只能等待/超时，不能算成功。可重试错误先重试，耗尽或不可恢复才报失败。⑤在 MVP 轮询结果，不依赖一定有修改事件。
9. **动态插件与无环多层传播是 MVP**：可信插件独立进程，动态持久登记、授权、消费者、启停、凭据更换/撤销和自动重判全部纳入；核心不得依赖插件，插件可依赖获权核心、其他插件和自己的结果。①对当前有效对象的最终依赖图强制无直接/间接自环，历史边不能永久阻止当前合法依赖；成环整批拒绝并定位，可靠处理并发。不是插件市场、自动安装启动、热升级或不可信代码沙箱。
10. **外部动作与界面边界**：保留日历、提醒事项业务；插件使用系统已有日历/提醒事项能力也必须建议→审核→执行，不得越权写④数据。结果未知停止自动重试，由用户核对；不承诺任意外部系统 exactly-once。⑥只有插件管理轻量 Web 页面是新增的 MVP 客户端例外，其余客户端不强制，原八步可用 API/测试客户端验收。
11. **契约与实现状态**：本轮只同步文档，不改代码或 Schema。`rule_selection`、`fields` 是已讨论术语，不代表现有 contracts 已支持；其他新增英文类型/状态/字段均属暂拟，准确标识待契约冻结。①负责人与 I 共同审核契约增补，只加不删、不改已有字段含义；具体待冻结项见第 6 节及术语表。

## 2. 各工作部分

### ① 存储与事件

**说明**：统一读写、版本、依赖和事件基础设施；新增动态模块管理，但不执行归属、提取或依赖调度业务判断。

**工作内容**
- 按 ADR 交付独立服务，保留 `StorageClient` 兼容目标和内存测试。PostgreSQL 同库按模块 schema 隔离，公共 storage 空间；不要求一类型一表，不允许插件直连数据库或任意 DDL。计算在服务外，批次事务在服务内。
- 实现去重、版本追加、整体替代终止、内容无变化不新增业务版本；统一当前/历史/id/类型/时间范围读取。
- NATS JetStream 配合 Outbox/Relay，至少一次投递、重投幂等、死信与恢复；成功写入的应发事件可靠送出，失败事务不发，系统记录不发。不把数据库与总线宣称为单一事务。
- 保存并比较字段依赖，落实强制完整登记、提交新鲜度检查和冲突整批拒绝；实现当前最终依赖图的可靠并发无环校验，禁止核心依赖插件。
- 动态持久登记命名空间、所属方、是否可重判、强制依赖要求、读取/写入/订阅权限和消费者状态，供①⑤无需重启或改业务代码发现。核心内置配置与动态登记并存，不再只靠启动配置。
- 管理反馈由⑥验证管理员并写入，①存储后发 `data_changed`，自己的管理处理器消费反馈并调用内部逻辑，**不是 HTTP 自调**。①单写登记、权限及管理结果，⑥查询；提交与执行时都复核可信授权，普通插件不能自行授权。
- 管理采用稳定请求 id、幂等且可恢复阶段；已受理不等于生效，相关组件就绪才启用。停用阻止新的访问/投递，不撤销已提交写入、不默认删数据；保留部署应急阻断，不作日常绕过页面的管理渠道。
- 权限默认拒绝，按类型批准读当前与历史，订阅单独批准且不超过读取范围；依赖引用需读权限，所有读/id/query/依赖接口均过滤。凭据不作普通数据类型暴露，新权限重新批准，不引入逐字段/逐记录 ACL。

**依赖**：I 的部署、身份与可靠投递联调；③④⑤⑥⑦和插件的所有权、依赖、结果、管理反馈契约。可先交兼容接口/测试替身并行，但完整交付不能脱离这些依赖。
**交出**：独立服务、兼容 SDK 目标、依赖及查询接口、可靠事件链路、动态管理基础设施及说明；具体协议/参数待实施设计，不宣称已经实现。

**验收标准**
- 同一原始数据不重复；历史不可变可读；整体替代 n+1、终止后拒写和重复替代幂等；无变化不新增业务版本/事件。
- 字段比较覆盖缺失/null、数组顺序、去重排序、A→B→A、对象整体替代；强制依赖缺登记拒绝、显式空集接受、无变化仍完整登记。
- 提交期间输入变化返回冲突并触发重读重算；直接、间接、批次内及并发成环均整批拒绝，合法新依赖不被旧历史边永久阻止。
- 重启、重复投递、Relay 故障、死信恢复不丢已提交事件、不重复业务效果；系统记录不引发事件循环。
- 动态插件登记、启停、撤权、换凭据、管理处理器恢复符合第 3 节；越权读取、订阅、依赖引用及写其他模块数据均被拒绝。

**实施方决定**：服务协议、表组织细节、索引、可靠并发算法、恢复参数；不得重新把已采纳的服务/数据库/总线选型作为未决产品项。
**工作特点**：多模块共同关键路径，应拆阶段交付接口、持久化、授权和动态管理，不再作为单一中等存储任务估算。

### ② 适配器

**说明**：把外部数据统一成输入格式，只做确定计算，不做推断；保留旧分解的全部业务。

**工作内容**
- 扫描 Octopus 目录的新文件，确认已写完再处理。
- 封装现有 Ear 基础处理模块，保留、不重写，输出录音引用、转写段、局部说话人、声纹、环境声。
- GPS 适配器每点一条；手机信息包括电量、屏幕、前台应用、Wi-Fi 等。
- 填好时间区间、设备/渠道/用户来源、适配器版本、去重键、大文件引用等统一字段。

**依赖**：①写入接口和可信凭据。
**交出**：入库原始数据；各类具体内容的字段说明供③④使用。
**验收标准**：真实数据所有文件可入库、不重不漏；重启重扫不重复；时间与真实时间对齐。数据天数、时间误差仍待确定，不虚构指标。
**实施方决定**：扫描方式、时间对齐、Ear 封装与调用、GPS 采样间隔。
**工作特点**：规则确定、边界清楚，需要熟悉 Ear 的参与者；不因插件扩展而重写原适配业务。

### ③ 归属模块

**说明**：保留参考、未命名人物、未知地点和用户确认保护；适配字段依赖及可靠重判完成协议。

**工作内容**
- 新声纹/GPS 尚无归属时处理：若已是某对象参考，直接归属；否则与有参考的对象匹配。认不出的声纹新建未命名人物并自动设置一次首个参考；认不出的 GPS 归属全局唯一未知地点，不自动新建地点，未知地点无参考、不参与匹配。
- 执行纠正、确认、增减参考、新建地点、命名/改名、按时间范围重新归属等反馈。纠正时从原对象参考中移除数据、加入目标对象参考并更新归属；确认时加入当前对象参考，保持一条数据最多属于一个对象的参考；用户明确创建地点时选中的 GPS 成为参考并归属到新地点。
- 人物参考清空后保留对象但不参与匹配；仍有声纹时提供“#N 还有 M 段声音，可能也是 X”的提示数据，无声纹时整体替代。
- 维护门控：纠正/确认附带的参考变化不自动重判其他历史归属；增减参考由用户选择。纠正后“同时重新判断其他相关记录”反馈交⑤处理，带纠正前后两个对象；依赖找不到的新候选可用按时间范围重新归属补救。
- 登记实际匹配输入及候选的字段依赖。只依赖参考的归属不因人物/地点名字变化而重判；首次命名/改名可使实际依赖名字的产物过时。
- 收到重判请求查当前状态，按当前参考处理，不推翻用户已纠正或确认的归属。写自己拥有的结果系统记录；即使输出不变，也同批刷新完整依赖、提交完成结果与消费标记。

**依赖**：①接口/身份/依赖/结果协议；②声纹和 GPS（初期可用假数据）；可能使用⑦；与⑤对齐重判协议。
**交出**：人物、地点、参考、归属及历史版本；完整依赖；自身重判结果记录。
**验收标准**
- 提取前待归属数据都有归属；一条数据最多是一个对象的参考；任何重判不推翻用户纠正/确认。
- 改名不触发仅使用参考的重新归属，实际读取名字者可被找出；参考改变且用户授权重判后，曾使用相关候选参考的归属不遗漏。
- 原未知地点、未命名人物、无参考不匹配、按范围补救场景通过；无变化重判有完成证据且不制造业务事件。
- D2 认人准确率达到后续确定的指标。
**实施方决定**：匹配算法、阈值、候选选择与未命名人物处理细节；依赖必须反映实际输入，不以“自行选择候选”省略已使用输入。
**工作特点**：算法工作保留，可先用简单匹配跑通；新增依赖与完成记录联调不可省略。

### ④ 活动提取模块

**说明**：保留活动划分、定时/手动提取、规则和建议业务，新增规则选择结果、规则新鲜度、纯 Markdown 与重判结果交付。

**工作内容**
- 定时器仍在④内部：从上次成功定时提取结束到现在，扣除所有已成功提取时间段（含手动）；放弃的范围不算成功。前置检查所有待归属数据已有归属，否则延后重试，超等待上限放弃并提示。
- 执行手动提取/重新提取、规则增删改、只改本次提取、规则应用到历史活动、审核建议、外部执行结果反馈。只改本次仍存单活动规则并立即提取；手动应用跳过自动选规则、追加结果。
- 活动划分及名称/描述仅用原始转写、时间、GPS、手机信息，不用推断人物/地点。纠正归属不重划活动；用户明确重新提取才整体替代范围内旧活动/产物并新建活动 id，执行前提示有多少活动带用户修改。
- 每活动维护一份版本化 `rule_selection`，④单写，登记实际输入和候选规则版本。相关输入变化由⑤请求后，重新查看全部当前有效规则，包括新增、不含删除。
- 新选中规则生成产物/建议；不再选中则整体替代其自动产物及未审核建议；仍选中不额外触发产物重算，产物按自身依赖处理，不直接依赖 `rule_selection`。手动应用产物不因自动选择变化撤销。
- md 正文直接写名字；依赖仍含活动、所用规则、活动范围内全部归属，另加实际输入的人物/地点字段。不可变的结构原始数据可不登记，不把字段依赖纳入 MVP 误写成取消归属粗粒度基线。
- 规则修改/删除本身不主动重算历史。历史产物被其他输入触发重判时，使用原规则当前版本；原规则删除/整体替代则整体替代产物及未审核建议，已审核/执行/拒绝建议不动，手动应用产物在此情况下也适用。不自动换另一条规则；记录额外规则版本变化/删除起因。
- 日历/提醒建议仍关联产物版本；产物变化时替代未审核建议并按新版生成。已批准、执行中、结果未知、已执行、已拒绝不当作未审核作废，也不随产物变化重做外部动作。执行结果仅经⑥反馈由④更新；插件建议与反馈交接待契约设计，插件不能写④数据。
- 处理产物和规则选择的重判请求，提供自身结果系统记录；成功业务写入、依赖刷新、完成记录、消费标记同批。规则集合新增、候选缺失等并发保护列入验证计划，不在本文虚构已经解决的协议。

**依赖**：①事务/依赖/新鲜度协议；③归属（初期假数据）；⑦；⑤完成调度；⑥反馈和外部动作；D2/D3。
**交出**：活动、规则、规则选择结果、纯 Markdown 产物、建议、提取记录及版本；完整依赖和自身重判结果。
**验收标准**
- 一整天真实数据可处理；活动边界符合待定 D2 指标，D3 正反规则选择通过；定时不漏不覆盖已成功范围。
- 改归属不重划活动；首次命名/改名仅使相关名字依赖者重判，不做显示时替换标记。
- **原规则版本也未变化时**，纠正未影响的 md 产物逐字不变；规则版本变化时使用当前版本，不能强求沿用旧版文本。
- 覆盖规则修改/删除不主动重算、其他输入触发使用当前规则、原规则删除时替代、选择新增/退出/仍选中、手动产物不随自动选择撤销、已审核建议保护。
- 结果不变时无业务新版本/事件，但依赖与完成记录可供⑤推进；规则并发和提交新鲜度有验证，不宣称现有 contracts 已覆盖。
**实施方决定**：提示词、长数据切分、活动划分及规则选择算法；不能变更已采纳的输入边界、规则版本语义和用户保护。
**工作特点**：大模型应用与跨模块协议工作量均大，需连续投入，不能仅按原提取器估算。

### ⑤ 依赖分析模块

**说明**：由固定核心链路扩为动态发现、多层无环依赖调度；传播记录仍为⑤单写，注册表由①管理。

**工作内容**
- 保留两个入口：符合门控的已有数据修改/整体替代，以及“同时重新判断其他相关记录”反馈。后者用纠正前后两个对象查询；规则变化本身不主动重算历史。通过①查当前有效、确已过时的依赖方，不只判断版本号。
- 读取新旧版本形成可读原因，按①登记的所属方和是否支持重判分发。目标包括归属、md 产物、规则选择结果、获准可重判的插件结果；新插件加入无需改⑤业务代码或重启⑤。
- 对已知相关受影响上游允许并行，下游等待这些上游完成；MVP 轮询各所属模块的结果系统记录，无变化也解除对应等待，不能只靠修改事件推进。
- 多起因尽量合并一次处理并保留全部追溯；不承诺持续输入下只重算一次，也不全局停顿。①提交新鲜度冲突时重读重算；跨 root 合并方式留契约设计，不丢弃任一起因。
- 失败、超时、插件停用或撤权造成下游等待/受阻，保留旧结果但明确可能过时、无法更新，不能冒充成功。上游删除/整体替代交下游所属方重判，①不级联删除；无有效结果须明确不可用或整体替代，不可用不默认为成功。
- 不以 md 为固定终点，不限制插件一两层；无下游或结果不变时相应传播路径结束，其他起因仍可触发。有限工作集且无新输入时有限步终止或明确阻塞/失败；持续输入不声称总任务有限。安全限额触发要记录并提示，不算成功完成。
- 记录根源、每步全部起因/目标、请求、完成结果和停下原因，关联⑦调用，提供论文实验统计与导出。

**依赖**：①字段依赖、无环、新鲜度、动态登记、结果读取与投递；③④及插件的完成协议；⑦调用追踪；⑥补处理选择。
**交出**：重判请求、调度与恢复、传播记录/统计；消费登记而非另建第二份静态所有权表。
**验收标准**
- D1 与冲突场景中的受影响结果不遗漏；用户按钮能找出相关归属。
- 无变化完成可推进下游，崩溃无结果、失败/超时/停用不假成功；上游并行、下游等待、菱形多原因及并发新输入可追溯。
- 跨插件及插件内部超过两层链路自动传播；当前图拒环；动态加入无需修改或重启①⑤。
- 有限静态工作集终止或明确受阻；深度/资源限制有错误或阻塞证据；原八步第 6、8 步通过。
**实施方决定**：调度算法、轮询间隔、去重/合并策略、安全限额及恢复细节，须满足上述语义。
**工作特点**：研究与可靠分布式调度并重，比原“查依赖后发请求”显著扩大。

### ⑥ 客户端与 API

**说明**：展示/读取、反馈、外部动作执行，不做推断。**只有插件管理轻量 Web 页面纳入 MVP 客户端例外；时间线、地图、人物、规则等完整客户端不强制开发，仍须具备 API/测试客户端可验收的业务入口。**

**工作内容**
- 保留时间线、活动、md、人物、地点、规则、建议的读取 API 和单人部署访问鉴权；插件管理另须验证管理员身份，不能把普通插件凭据视作管理员或沿用自报身份。
- 提供反馈入口：纠正/确认、增减参考及是否重判、命名、选 GPS 新建地点、按时间范围重新归属、规则管理/只改本次/应用历史、手动提取/重新提取、建议审核、执行结果。纠正后按钮等价操作携带前后两个对象交⑤；返回“#N 仍有声音”和重新提取用户修改数量等提示数据。
- 正文按纯 Markdown 展示；不再要求人物/地点特殊引用标记渲染器。非插件页面可用 API/测试客户端呈现上述提示和操作，不把原“每项都有页面”继续列为强制验收。
- 实现插件轻量 Web 管理页面及 API：登记、权限审批、启用、停用、凭据更换/撤销、状态/失败原因查看、历史补处理和恢复选择。⑥验证管理员后写管理反馈，①异步自消费并写管理结果，页面查询已受理/处理中/生效或失败，不能受理即显示已启用。
- 配合①区分首次启用（仅自动处理启用后变化）、主动停用后恢复（提示遗漏，用户选补或跳）、意外断线/重启（自动续处理）。历史上下文读取不等于历史批量生成授权；补处理范围由用户显式选择，查当前状态不盲重放旧事件；跳过不把旧结果标新。
- 必须处理建议已通过的事件，但先查当前状态；外部执行用稳定动作标识及外部可靠幂等/查证能力。可查证成功不重做，明确未执行才重试；结果未知停止自动重试、提示核对，支持确认已执行或明确重试并提示重复风险。
- 执行结果仍由⑥写反馈、④更新建议；不承诺本地消费标记能保证任意外部 exactly-once，不禁止为恢复记录必要的外部标识。插件使用系统已有日历/提醒事项能力也不得绕过建议→审核→执行，具体交接协议待冻结。

**依赖**：①身份/管理/读取接口；③④⑤反馈语义；外部执行能力；I 和插件生命周期联调。
**交出**：业务 API、反馈格式协作说明、外部执行与恢复能力、插件管理轻量页面/API；非插件完整客户端不作为必交物。
**验收标准**
- 原用户修改清单都可通过 API/测试客户端操作并写正确反馈、查看异步状态和提示。
- 管理页面可完成可信插件授权全流程；普通身份不能自授权；①未实际就绪前不显示生效，失败可查。
- 原八步第 4、5、7 步通过 API/测试客户端成立；外部日历/提醒的预期效果可核验，无需开发完整手机 App。
- 重复事件不盲重做；故障窗口出现未知时停止自动重试，用户核对/明确重试有重复风险提示；已批准、执行中、未知不被当未审核作废。
**实施方决定**：轻量页面技术、API 展示形式、可选推送；协议与恢复实现不得绕过单写边界和用户授权。
**工作特点**：不再估完整前端客户端，但身份、异步管理、恢复链路增加，不能认定相对独立或工作量不变。

### ⑦ 大模型入口

**说明**：复用 Octopus 接入基础形成独立服务；调用记录经①统一持久保存，⑦单写、不发事件。

**工作内容**
- 独立 docker 服务对接反代平台，统一换模型、限流、重试；所有模块及插件经本入口调用。
- 默认记录 metadata：调用模块、根源反馈、用途、用量、耗时及追踪关联；重判调用携带请求 id，可与⑤传播步骤关联。
- 默认不保存提示词/回复正文，仅显式按需开启；这不影响④或插件正常保存业务产物正文。正文保留期限、作用域等留实施参数设计。
- 统计按模块/根源汇总，记录经①保存为⑦拥有的系统记录。逐次尝试日志粒度仅为实施建议，不能写成本轮已独立批准的精确粒度。

**依赖**：①系统记录持久化、身份与读取接口；⑤请求关联约定；I 服务部署；Octopus 接入基础。
**交出**：调用服务/接口、统一存储的 metadata 记录、按需正文开关、统计与追踪查询。
**验收标准**：无调用方模块则拒绝；按模块/根源统计；重判可关联请求和传播记录；默认无提示词/回复正文、显式启用才保存；日志写入不发事件。
**实施方决定**：接入方式、限流重试、日志粒度建议与保留参数，不能改变默认正文关闭和统一存①的已采纳边界。
**工作特点**：复用基础仍需持久化、身份及追踪联调，从原“小、无依赖”上调为中等估算。

### D1 模拟组会

**工作内容**
- 编写组会脚本：几位组员各说几段，含明确待办，地点在实验室；至少一个需纠正的认人场景，覆盖八步第 5、6 步。
- 按脚本录制并采集 GPS，整理谁在何时说话、活动边界、待办、建议及纠正后答案。
- 保留原演示数据职责；插件和恢复专项用额外合成 fixtures，不要求真实录音承担所有故障场景。
**交出**：录音/GPS 和标准答案；仓库仅保存脚本、标准答案及合成假数据，真实录音、GPS、姓名不入库。
**验收标准**：②可正常入库，标准答案足以判断原八步每步是否正确。
**工作特点**：基础量小，录制需要共同参与；参与人和日期未定。

### D2 标注数据

**工作内容**：从获录音提供者同意的真实数据中选取样本，标注每段声音的人物及活动起止和类型；数量待定，不扩张授权用途。
**交出**：标注文件及格式说明，真实标注留仓库外。
**验收标准**：可用于③认人准确率、④活动边界一致度计算。
**工作特点**：中等且耗时，宜由了解录音人物的提供者参与；不虚构标注人或完成量。

### D3 规则测试集

**工作内容**
- 保留组会、上课、闲聊等常见规则，覆盖条件规则、外部动作规则及每条规则的应触发/不应触发活动例子。
- 增加规则选择结果变化、原规则当前版本/删除、手动与自动产物区分、规则版本未变时逐字不变等回归样例。
**交出**：规则和预期结果测试集。
**验收标准**：可直接验证④规则选择与本轮规则重判语义；区分“选择仍适用”与“产物依自身依赖需要重算”。
**工作特点**：原基础集小，可碎片化编写；新增组合回归随④/I一起评估，不隐含原排期不变。

### I 集成与端到端验收

**工作内容**
- 保留一人一套、docker compose、一键部署目标；按 ADR 集成①独立服务、PostgreSQL、NATS JetStream 与 Outbox/Relay、可信插件独立进程和⑦。这里只列交付任务，本轮不修改部署。
- 维护公共约定，协同各模块冻结契约与接口，核对设计/Schema/实现/测试偏差，组织故障和并发联调。
- 保留 D1 原八步的业务结果，用 API/测试客户端替代强制 App：

  | 步骤 | 必须验证的结果 | 模块 |
  |---|---|---|
  | 1 | 组会录音和 GPS 入库 | ② |
  | 2 | 声纹归属人物、GPS 归属地点 | ③ |
  | 3 | 定时划分组会活动，生成笔记/待办 md 和提醒建议 | ④ |
  | 4 | 用 API/测试客户端读取时间线及纯 Markdown 产物 | ⑥ |
  | 5 | 提交“A 不是甲，是乙”的纠正反馈 | ⑥→③ |
  | 6 | 待办负责人改乙，未审核建议重新生成；原规则版本未变且未受影响的产物逐字不变 | ③④⑤ |
  | 7 | 审核通过并执行，目标日历/提醒系统出现正确内容，执行结果反馈更新建议 | ⑥→④ |
  | 8 | 查出纠正的完整传播、含无变化完成结果及关联的大模型调用 | ⑤⑦，记录统一经①保存 |

- 用真实数据连续跑完一整天，检查不中断；将原八步和第 3 节新增插件验收固化回归，学期末演示仍可用 D1。
**交出**：部署、契约协作、原八步及插件/可靠性验收记录、可重复回归与演示流程。
**验收标准**：原八步、整天可靠性及第 3 节新增验收共同通过，不能只用八步完成代替扩大后的 MVP。
**工作特点**：持续且跨模块，范围显著扩大；谁负责及是否兼任由负责人另行决定。

## 3. 新增插件与跨模块验收矩阵

插件定义只在[插件 MVP](plugins-mvp.md)维护；下表将其转成交付门槛，不指定未批准的协议或类型名。最小测试插件使用合成数据，业务产品化插件不因这些测试而自动进入 MVP。

| 场景 | 通过条件 | 协作部分 |
|---|---|---|
| 动态登记与单所属方 | 管理页提交后异步生效；登记持久且①⑤无需重启/修改业务代码；类型所属方就是唯一写者和重判执行方 | ①⑤⑥I、测试插件 |
| 管理幂等与失败恢复 | 只有两种总线事件；①自消费管理反馈，重复请求不重复效果；提交/执行复核授权，阶段失败可恢复，受理不假装启用 | ①⑥I |
| 权限与凭据 | 默认拒绝；读当前/历史/id/query/依赖及订阅均按类型过滤；订阅不超读权限，跨空间写和自授权被拒；换凭据/撤销生效 | ①⑥I、测试插件 |
| 生命周期 | 首次启用不自动生成历史结果；主动停用恢复可选补/跳，意外断线重启自动续处理；停用阻新访问/投递、不撤销已提交写入、不删数据 | ①⑤⑥I |
| 历史和撤权 | 读历史上下文不等于批量历史生成；显式补处理查当前状态；跳过保留旧结果且不标新；撤权保留旧结果并标无法更新，恢复补处理由用户选 | ①⑤⑥I、测试插件 |
| 多层传播 | 验证核心→插件→其他插件及同插件内部超过两层的链路和分叉/汇合；核心不能依赖插件；无固定 md 终点 | ①⑤I、测试插件 |
| 无环与并发 | 直接自环、间接环、批次最终图成环及并发造环整批拒绝且有定位；历史边不永久禁止当前合法图 | ①I |
| 完整依赖与新鲜度 | 必须登记的类型含无变化 Update 仍完整登记；缺登记拒绝、真无依赖显式空集；提交时输入变更冲突重算 | ①③④I、测试插件 |
| 调度与无变化 | 已知相关上游可并行，下游等完成；无变化有结果记录且可推进；多起因尽量合并并保留全部追溯 | ③④⑤⑦I、测试插件 |
| 失败与终止 | 崩溃无结果、失败/超时/停用使相关下游等待/受阻；无新输入有限工作集终止或明确阻塞，安全限额不是成功 | ①⑤I、测试插件 |
| 上游整体替代 | ①不级联删，下游所属方重判；无有效结果明确不可用或整体替代，不把不可用默认计成功 | ①③④⑤I、测试插件 |
| 插件外部动作 | 建议→审核→执行不可绕过，插件不写④数据；未知停自动重试，用户核对/明确重试提示重复风险 | ④⑥I、测试插件 |
| 调用日志 | 插件也经⑦；默认 metadata、正文显式开启；⑦单写日志经①保存、不发事件，重判关联请求 | ①⑦I、测试插件 |

## 4. 阶段与并行方式

阶段是依赖和验收门槛，不是已承诺日程。阶段内可用模拟接口并行，但不能以替身通过等同持久服务或故障验收通过。

| 阶段 | 交付目标 | 退出门槛与可并行工作 |
|---|---|---|
| 0：契约与范围对齐 | 对齐本轮决定、所有权、结果/管理/权限/依赖接口及待冻结项；重新评估工作量 | ①/I协同各模块形成契约冻结清单与兼容方案；D1脚本、D3基础例子、D2样本选择可并行，负责人/指标/日期另定 |
| 1：基础设施与测试替身 | ①接口和兼容测试、独立存储/事务/可靠投递/身份基础；⑦统一记录接入 | 去重/版本/整体替代/权限/完整依赖/新鲜度有基础验收；②③④⑥可基于约定和假数据并行，⑦不能脱离①视作完成 |
| 2：核心业务与完成闭环 | 保留②③业务，完成④规则选择/纯md/规则新鲜度、③④完成结果、⑤轮询调度、⑥外部未知恢复 | 原八步可由 API/测试客户端验证；无变化、规则变化与失败有明确证据。动态管理页面/API及测试插件可与核心联调并行 |
| 3：动态插件与多层可靠性 | 动态持久登记、管理员反馈自消费、权限/凭据/启停、历史补处理、跨/同插件多层无环调度 | 第 3 节矩阵覆盖正常、重启、撤权、并发造环、上游失败、未知外部结果；不以“不做市场”删去动态插件工作 |
| 4：集成与回归 | I汇总部署、真实数据整天可靠性、原八步和插件专项回归 | 已知偏差/未冻结契约/未验证恢复场景逐项报告，不能以文档 accepted 或局部测试通过宣称 MVP 全完成 |

## 5. 不在本轮 MVP 内

- 插件市场、自动安装/启动插件代码、不可信代码沙箱、热升级；可信插件独立进程并不提供沙箱安全保证。
- 强制完整时间线/地图/移动端客户端、通用插件输出展示页；仅插件管理轻量页面为例外。
- 有环依赖传播、核心反向依赖插件；多层无环和字段依赖已经纳入，不能再列为以后。
- 检索索引⑧、问答/按需补充、多用户、针对人的隐私控制、合并人物、直接编辑活动/md、自动触发提取、补传数据检测、跨定时边界活动、更多输入渠道等仍沿用以后方向；本轮插件类型权限不等于逐字段/逐条隐私 ACL。
- 社交/习惯等具体产品化插件不是必交成品；但用于证明动态注册、权限、多层依赖与动作闭环的测试插件及验收不可推迟。
- 新增外部系统动作类型仍不在本轮MVP；插件使用系统已有日历/提醒事项能力的受控通路纳入MVP，仍走建议与审核，不包括插件自定义执行器或新动作提供机制，也不承诺任意外部 exactly-once。
