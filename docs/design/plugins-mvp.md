# 动态插件系统：MVP 行为与边界

本页定义已采纳的目标，**不是已有插件框架的使用说明**。依据见[决策索引](../decisions/mvp-confirmed-decisions.md)，核心行为见[设计 v1.2](design-v1.2.md)，分工见[工作分解](work-breakdown-v1.2.md)，实现差距见[实施计划](../../ai-docs/plans/mvp-implementation.md)。

## 1. MVP 要做到什么

管理员可在系统运行中注册、授权、启用、停用一个可信插件。插件是独立进程，使用 SDK 访问①和⑦、按权限消费事件，不加载到①的进程内。新增插件无需修改①⑤业务代码或重启这两个服务。

插件是模块：有自己的稳定身份、逻辑数据空间、所拥有的数据类型、是否支持重新判断的声明，以及明确批准的读取与订阅范围。核心类型由内置定义初始化，插件登记持久化并动态生效，不再只有启动时的静态配置。

**不纳入 MVP**：插件市场、代码上传后自动执行、自动下载安装/启动、复杂热升级、不可信代码沙箱、任意 SQL/DDL、通用插件结果展示页。⑥轻量插件管理页是已纳入的客户端例外，不等于整套客户端都要实现。具体社交/习惯等业务插件不是自动新增的交付要求；应有合成示例插件用于接入与多层验收。

## 2. 所有权和管理职责

| 部分 | 职责 |
|---|---|
| ⑥ | 轻量管理页面/API、验证管理员身份、写管理反馈、查询受理/执行结果 |
| ① | 管理反馈处理器、持久登记、空间与凭据、权限校验、事件访问控制、管理任务结果 |
| ⑤ | 动态发现支持重判且可用的类型，按所属模块分发、等待和追踪，不控制插件安装 |
| ⑦ | 插件的模型调用入口，单写调用记录并通过①保存 |
| 插件 | 自己的计算逻辑、自有数据和重判完成记录，遵守输入依赖与幂等约定 |
| I | 独立进程部署方式、整体联调、恢复和应急阻断操作说明 |

每种业务数据只有一个写入方。重新判断由同一个所属模块执行，注册表只需另声明是否支持重判，不再配置第二个执行人。①拥有公共依赖索引、Outbox及消费标记的管理机制，但不借此改变其他模块的业务数据。

每个插件有自己的 PostgreSQL schema/逻辑空间，由①创建和管理；插件不拿数据库直连或管理凭据。类型名/命名空间不能冒充核心或其他插件；唯一命名、迁移格式和版本兼容策略属于待实施的注册协议。

## 3. 管理页面与异步反馈

页面提供：列表、登记声明、权限申请/批准、启用/停用、凭据更换/撤销、运行状态及错误。必须区分“已启用”和“进程在线”，也区分“已受理”和“已生效”。

正常流程统一如下：

```text
管理员操作⑥
 → ⑥验证管理员，向①写管理反馈（⑥单写）
 → ①保存反馈和待发事件
 → data_changed 到①内部管理处理器
 → 再核对可信授权和当前状态，执行内部管理逻辑
 → ①写登记/权限及管理执行结果（①单写）
 → ⑥查询结果并更新页面
```

不 HTTP 自调，不新增第三种事件；管理执行结果是系统记录，不再发反馈来推进自己。①从“只发不收”调整为**只消费自己的管理反馈**，不接管归属、提取或传播业务。

管理反馈不能仅靠正文 `admin=true` 获权；提交和执行都检查可信身份，排队期间撤销的授权不得继续使用。普通插件无权给自己注册新身份或扩大权限。反馈/结果不能泄露凭据；凭据展示和交付须走专门受保护渠道，准确协议待实现。

## 4. 生命周期和恢复

- **注册**：管理员批准身份、类型、请求权限；不代表资源已经创建或程序已启动。
- **启用**：空间、身份、访问策略和消费配置就绪后才允许访问。状态阶段和执行结果可查询。
- **停用**：阻止新的访问与任务投递，不撤销已经提交的写入，不默认删除数据；在途处理如何截止必须在实施中实现可验证的生效边界。
- **查看状态**：区分配置状态、运行连接、执行中的管理任务及其失败。
- **更换/撤销凭据**：不需删除数据；失效身份不能继续访问。
- **卸载/删除**：停用不是删除，删除数据须单独确认；MVP页面不承担自动卸载进程或一键清空数据。

管理操作使用稳定请求ID，重复事件不能重复创建资源。跨PostgreSQL、总线、消费者和权限配置采用可恢复步骤，**不承诺一个跨系统数据库事务**。失败保留进度，可重试或补偿；未完全就绪不能标“可用”。

异步管理在总线不可用时可能不能及时执行，因此保留部署管理员的紧急阻断手段，并记录审计；它不是普通插件或日常页面绕过反馈的入口。具体命令和恢复流程写入工程文档，不在此虚构现成命令。

## 5. 按数据类型授权

| 能力 | 边界 |
|---|---|
| 写入 | 仅写自有业务类型，经①统一校验版本、事务和依赖 |
| 读取 | 核心及其他插件数据默认拒绝，按类型由管理员明确批准 |
| 版本范围 | 同一读取授权覆盖当前与历史，仍受终止/查询过滤语义约束 |
| 订阅 | 单独批准且不得超过获准读取的类型范围；不能先全量投递再仅由插件过滤 |
| 登记依赖 | 只能引用有读取权限的对象；完整登记、当前有效图无环；核心不能依赖插件 |
| 管理敏感信息 | 凭据等不作为普通类型公开，不因能查登记表就能读密钥 |
| 升级权限 | 新增权限重新申请，不静默扩大 |

①在按ID、历史、批量、条件查询、计数和依赖等所有读取路径执行授权。事件不携带正文也仍可能泄露对象存在或关系，订阅和请求路由同样需要限制。⑤作为受信任调度方需要完成职责所需的访问，但不能借其请求把未授权输入转交给插件。

MVP不做逐字段/逐条记录ACL；`fields`是依赖失效选择，不是读取权限。可信独立进程不等于沙箱，系统不能保证插件程序不会自行联网；管理权限承诺针对系统接口和总线能力。

## 6. 首次接入、历史和断线

| 场景 | 行为 |
|---|---|
| 首次启用 | 默认只自动处理启用后变化，不批量生成过去结果 |
| 用户要求历史补处理 | 明确选择时间范围，启动可追踪任务 |
| 主动停用后恢复 | 提示期间有未处理变化，用户选择补或跳 |
| 已启用进程意外断线/重启 | 自动续处理未完成任务，不反复要求确认 |
| 读取历史作当前任务上下文 | 在权限内允许，不等于获准批量生成历史产物 |

补处理基于当前状态，不盲执行每条旧事件。选择跳过不表示旧结果已更新，保留并可标“依赖过时、未重判”，以后可主动补处理。停用下游/上游对传播的阻塞按主设计处理。

消息保留期限、首次接入的快照/游标交接、断线跨越保留窗口后的补偿方案需在实现中明确。不得假设事件永久保存或恢复游标就一定覆盖所有已发生变化；实现必须验证不漏处理和权限/历史选择边界。

## 7. 多层自动依赖与重判

允许核心→插件、插件→插件、插件内部结果之间的多层依赖；不限制一两层，仍禁止核心反向依赖插件。①依据当前有效对象的最终依赖图检查自环/间接环，成环整批拒绝并定位；历史边不永久禁止当前合法关系，批内及并发形成的环也必须防住。

⑤按动态所有权与重判能力路由：已知相关受影响上游可以并行，下游等完成；多原因尽量合并而不丢追溯；无变化也完成，不新增业务事件。持续输入可以产生后续轮次，不承诺全局只算一次。失败/超时/停用阻塞下游，保留旧结果，不假装最新；安全限制触发必须可见，不当成功。

每个可重判插件须有自己单写的完成系统记录，不能只给③④实现此能力。成功结果、完整依赖、完成记录和消费标记同批；无变化刷新依赖并记完成。⑤查询记录推进，不靠第三种事件。需依赖类型缺登记整批拒，显式空集与遗漏不同。

上游删除/整体替代时，由下游所属方重判，不由①级联删除；无法产生有效结果则明确不可用或整体替代。若来源权限被撤销，插件不再获准读取，已有产物保留且标无法更新，不自动删；恢复权限后补处理仍由用户选。

## 8. 模型、输出和外部动作

插件经⑦调用模型，带可信调用方、根源以及重判请求ID；⑦经①保存统计追踪记录，正文按需开启。插件文本输出用纯Markdown，可提供依赖和来源信息，不要求从正文猜实体ID。

插件使用系统提供的外部动作能力时，必须建议→用户审核→执行，不能通过SDK/事件绕过；未知执行结果暂停自动重试，已批准/执行中/未知不随产物变化当作未审核重做。此限制不冒充独立进程沙箱能力。

插件建议、审核/执行结果的所有权交接须明确契约。插件不直接写④拥有的建议；⑥仍只能写反馈而非篡改其他模块业务结果。具体桥接方式列入实施计划，不在本轮擅自确定第三种事件或多写入方类型。

## 9. MVP 验收

1. 用合成示例插件注册、自有类型和命名空间就绪；①⑤不改业务代码、不重启即可识别。
2. ⑥管理页完成正常反馈流程，重复管理事件不重复建资源；部分失败可恢复，受理不冒充生效。
3. 冒充模块、越权读/写/订阅、未经批准扩权、通过依赖接口窥探均被阻止。
4. 三层或分叉汇合的示例依赖自动更新；无变化释放等待，多原因完整追溯；自环、间接环及并发成环拒绝。
5. 上游失败/停用/权限撤销不让下游冒充最新；替代不由①级联删除，用户可看到阻塞状态。
6. 首次启用不自动补历史，手动范围补处理生效；主动停用恢复可补/跳；意外断线自动续处理；重放不重复生效。
7. 停用和撤凭据在生效后阻止新访问，数据仍保留；总线故障有部署应急阻断说明与测试。
8. 插件外部动作走审核，结果未知不盲重试；无未经授权的模型正文日志留存。

这些是尚待实现验证的验收目标，不是当前仓库测试已经覆盖的声明。
