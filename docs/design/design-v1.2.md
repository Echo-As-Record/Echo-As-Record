## 0. 阅读说明

### 0.1 范围与标记

- **【MVP】**：本轮原型须实现并验收；**【预留】**：不实现但不堵死扩展；**【以后】**：后续方向。
- 本文规定产品行为、模块边界、交接语义与验收。实现组织、算法、提示词、阈值及未定协议参数由实施设计明确；已明确采纳的选型见 ADR。
- `rule_selection` 是已采纳的逻辑结果名称；多起因、重新判断结果、管理反馈等新增类型和状态的准确英文标识，以及 `fields` 的接口位置，仍待契约同步。下文中文状态描述不是已存在的枚举。
- 本轮只同步文档，不改公共契约与代码。现有接口与目标不一致时须显式报告，不以本文假定接口已可用；契约演进仍遵守只增加、不删除或改义的约束。

### 0.2 总原则

- 确定处理的原始数据与推断的语义信息分开；原始数据只追加，版本历史不可变。
- 用户纠正或确认过的归属，不被自动重判推翻。规则编辑、参考更新的历史门控、手动重新提取及插件历史补处理分别遵循明确授权，不能笼统等同于自动重算全部历史。
- 一类数据一个写入模块；模块只经 ① 写自己的逻辑空间。模块所属方就是其结果的重判执行方。
- 当前有效对象的依赖图必须为有向无环图（DAG）；支持核心到插件、跨插件和插件内部的多层更新，核心不能依赖插件。
- 结果不变不新增业务版本、不发业务修改事件，但仍须刷新依赖并记录重判完成。
- 查当前状态、事务提交和幂等处理共同保障内部一致性；不向任意外部系统承诺 exactly-once。

### 0.3 术语

| 术语 | 含义 |
|---|---|
| 归属关系 | 声纹属于哪个人物、GPS 点属于哪个地点 |
| 参考 | 用户认可、用于认出人物或地点的原始数据 |
| 依赖分析 | 输入变化后识别过时结果，等待相关上游完成，再请求所属模块重判 |
| md 产物 | 从活动按规则生成的纯 Markdown 笔记、待办等 |
| 外部动作建议 | 须用户审核后才能执行的外部操作 |
| 根源反馈 | 触发一条因果链的最初反馈；系统发起时为 `system` |
| 整体替代 | 给对象追加终止版本，不是修改它的历史行，也不是级联删除 |
| 重新判断结果记录 | 由执行模块单写的系统记录，⑤ 据此确认请求是否完成，包括无变化结果 |

## 1. 产品概述

Ear 是面向个人部署的活动建模服务，持续收集录音、GPS、手机信息等数据，把每天整理成活动，识别相关人物与地点，按用户自然语言规则生成笔记、待办及日历、提醒事项的操作建议。用户纠正一处后，相关派生结果可自动更新，不必逐条修改。

### 1.1 功能与边界

- 【MVP】录音、GPS、手机信息走各自适配器；【以后】邮箱、自研 App 等新增渠道。
- 【MVP】认不出的人建立未命名人物，同一陌生人再次出现可归到一起；人物、地点、活动和产物保留历史。
- 【MVP】规则面向单个活动，可自动选择，也可手动应用到历史活动；外部动作一律先建议、后审核、再执行。
- 【MVP】可信插件的动态注册、授权和多层自动更新；跨活动汇总可由插件提供。插件管理的完整定义见[插件设计](plugins-mvp.md)。具体社交、习惯插件不因此自动成为 MVP 必做项。
- 【以后】⑧ 检索索引为其他 Agent 提供 RAG；问答、按需补充仍非 MVP。
- 【MVP】一人一套独立服务，人物、地点、规则不跨用户共享。用户 API 保留访问令牌保护；管理员与插件使用可信身份和独立授权，不能把一个用户令牌视为插件的无限权限。
- 【MVP】以服务端 API 为主，不要求完整客户端；⑥ 的轻量插件 Web 管理页面/API 是明确纳入的客户端例外。时间线与结果可通过 API 和验收工具查看。
- 【预留】原始数据来源记录用户；【以后】多用户仍按用户完全隔离。数据归用户所有，真实数据和凭据不进仓库。

## 2. 总体架构

### 2.1 模块与所有权

| 编号 | 模块 | 职责 |
|---|---|---|
| ① | 存储与事件 | 独立存储服务、统一 SDK、权限、版本、依赖与新鲜度校验、无环检查、事件投递及管理反馈处理 |
| ② | 适配器 | 外部数据转换、去重入库 |
| ③ | 归属模块 | 人物、地点、参考及归属关系 |
| ④ | 活动提取模块 | 定时/手动提取、活动、规则、选规则结果、md 产物及外部动作建议 |
| ⑤ | 依赖分析模块 | 识别受影响对象、上游等待、合并起因、发重判请求、查询结果与记录传播 |
| ⑥ | 客户端与 API | 用户/管理反馈、建议审核入口、外部动作执行、轻量插件管理页面/API |
| ⑦ | 大模型入口 | 统一模型调用、统计追踪与调用记录 |
| 插件 | 动态运行模块 | 获授权读取/订阅、只写自己的类型、按登记能力参加重判 |
| ⑧ | 检索索引模块【以后】 | 产物切片、向量化和 Agent 检索 |

模块业务通信使用两类总线事件；读写 ①、调用 ⑦ 直接进行，不经总线。计算在存储事务外完成，批次校验及提交在 ① 内部完成。

### 2.2 已采纳架构选择与数据流

- ① 为独立服务，保留 `StorageClient` 兼容目标及内存测试路径。身份由可信凭据确定，不信任请求自报模块名作为授权依据。
- PostgreSQL 同库按模块 schema 分逻辑空间，公共机制归 `storage` 空间；不是每个数据类型建一张表。插件不得直连数据库或任意执行 DDL。
- NATS JetStream 配合 Outbox/Relay，至少一次投递，提供重投幂等、死信及恢复。数据库与总线不被描述为一个跨系统原子事务。
- 核心内置配置加动态持久注册，不局限于启动时登记。①、⑤ 动态发现获准类型和消费者，无须修改业务代码或重启 ①、⑤。
- 上述为目标，具体 HTTP 等协议、版本、参数和恢复细节见后续实施设计，不宣称现有代码已实现。

```text
外部数据 → ② → ① → 按授权订阅投递数据库被修改 → ③ / ④ / ⑤ / ⑥ / 插件
用户操作 → ⑥ 写反馈 → ① → 对应执行模块
管理操作 → ⑥ 验证管理员并写管理反馈 → ① → ①管理处理器 → 管理结果供⑥查询
⑤ → 按类型所有者分发请求重新判断 → ③ / ④ / 可重判插件
执行模块 → ① 同批业务结果、依赖与完成记录 → ⑤查询完成情况、推进下游
所有模型调用 → ⑦ → ①统一保存调用系统记录（不发事件）
```

投递按授权事件范围过滤，不是全量广播后只靠消费者忽略。① 只消费其管理职责的反馈，不接管③④⑤业务。

## 3. 数据与依赖

### 3.1 分类【MVP】

| 类别 | 内容 | 规则 |
|---|---|---|
| 原始数据 | 录音引用、转写段、局部说话人、声纹、环境声、GPS、手机信息、用户反馈 | 只追加，版本固定为 1 |
| 语义信息与归属关系 | 人物、地点、参考、活动、选规则结果、md 产物、外部动作建议和插件结果 | 固定 id，追加新版本 |
| 提取规则 | 适用范围、提取内容、可选动作 | 版本化；编辑本身不主动重算历史 |
| 系统记录 | 依赖登记、提取记录、传播记录、重判结果、调用记录、事件/消费记录、管理操作结果等 | 不发业务修改事件，分别明确单写者 |

不使用置信度。声纹和转写由基础模型确定处理产生，按原始数据管理；大文件只存路径及哈希引用。类型准确标识和注册分类在契约同步时确定。

### 3.2 不可变版本模型（R6）【MVP】

- 语义信息、归属关系及规则的 id 永远不变；修改追加版本 `n+1`，**旧版本的内容和写入时 status 均不可变**。最大版本为 current，历史行仍为 `active` 不代表该行当前有效。
- 整体替代追加一个内容与版本 `n` 相同、状态为 `superseded` 的 `n+1` 终止版本；事件的 `old_version=n`、`new_version=n+1`，操作表示整体替代，不原地回写旧记录。
- 终止后拒绝继续写该对象；重复替代不新增版本、不重复产生事件。默认查询排除终止对象，按 id 或历史版本仍可读取（服从权限）。
- 原始数据版本固定为 1，所有数据统一按对象和版本引用。MVP 不做对象合并。
- 人物地点名字直接写进 Markdown；活动名称描述只使用原始数据，见第 7 节。不存在通过显示层替换特殊引用标记规避重判的约定。

### 3.3 统一原始输入格式【MVP】

每条原始数据至少包括：id、类型、版本号、事件时间区间、入库时间、来源（设备/渠道/用户）、适配器版本、去重键及数据。事件时间与入库时间分开；点事件允许起止时间相同。时间使用 UTC/RFC 3339，区间采用 `[start, end)`。

去重键由适配器计算，例如设备加文件哈希；相同输入重复送达只入库一次。模型或适配器重新处理产生新批次，旧原始数据保留。

### 3.4 需归属的数据与适配器【MVP】

- 声纹归属到人物，GPS 点归属到地点；不设停留段，GPS 每隔一到几分钟采点，间隔由适配器负责人决定。转写、手机信息、用户反馈无需归属。
- 刚写入未处理的数据可以没有归属；处理过的必须有归属对象，以是否有归属判断，不另设处理状态字段。
- 声音适配器封装现有 Ear 基础处理模块，不重写；输出录音引用、转写段、局部说话人、声纹及环境声。GPS 和手机信息各有适配器；扫描服务发现 Octopus 目录的新文件后分派处理。
- 用户反馈适配器属于⑥；更多输入渠道按同一输入约定接入。

### 3.5 字段级依赖与强制登记【MVP】

- 依赖记录指向输入对象及读取版本；`fields` 可选，省略时按全对象版本判断过时。
- 指定 `fields` 时，仅选 `payload` 顶层字段；① 比较登记版本与当前版本所选字段的**完整 JSON 值**，任一不同即过时。空数组拒绝；重复字段去重并排序；缺失与 `null` 不同，数组顺序有意义。
- 同一对象字段 A→B→A 时，按当前值比较可不再过时；已发出的请求不自动撤回。上游整体替代无论字段值是否相同均使依赖过时。
- ③、④ 和插件登记真实计算输入；不可变的结构性原始数据可不登记。① 保存并比较依赖，但不能代业务方判断输入是否真实完整。
- 注册表声明需登记依赖的类型（能力名 `requires_dependencies` 暂拟），其新建、更新、内容无变化的 Update 都须同批提交**完整依赖集**；不自动继承。确无依赖可显式空集，漏登记整批拒绝。
- 整体替代免新依赖登记，保留历史依赖。① 校验对象/版本存在、引用合法、读取权限、依赖新鲜度及当前最终依赖图无环；冲突拒绝后业务方重读重算。
- md 产物仍粗粒度依赖所属活动、所用规则版本及活动范围内全部归属关系，并增加实际放入计算输入的人物、地点字段。不得因支持字段依赖就移除该粗粒度保证。
- `fields` 所在层级、接口结构和新能力标识待契约设计；不得默认为当前 SDK 已具备。

## 4. 事件【MVP】

### 4.1 仅两类总线事件

| 事件 | 发出方 | 内容与作用 |
|---|---|---|
| 数据库被修改（`data_changed`） | ① | 原始/业务数据及规则提交后通知；包含类型、id、操作、新旧版本、根源反馈、深度及历史门控信息；系统记录不发事件 |
| 请求重新判断 | ⑤ | 目标类型/id、起因对象及新旧版本、可读变化说明、根源反馈及深度；投递给登记的所属模块 |

事件不携带业务正文，消费者按权限读当前状态及需要的历史版本。重判结果、管理完成结果靠系统记录查询，不新增第三种事件。

### 4.2 一致性与追溯

- 写入成功必须可靠地最终投递对应事件，失败不发；Outbox/Relay 支持至少一次，消费者必须处理重复投递。
- 先查当前状态，再结合消费标记、请求身份及同批提交保证幂等，不能只靠一次状态查询防止并发重复。
- 业务内容不变不新增版本、不发修改事件；系统记录和依赖仍可更新。
- 反馈直接产生的修改以反馈 id 为根源、深度为 0；系统行为使用 `system`。⑤ 发请求时沿因果路径增加深度，执行模块写入沿用请求上下文。
- 多个原因尽量合并一次重判，并保留全部 cause 和根源追溯。跨 root 的合并字段及与既有单 cause、`root_feedback_id`、`depth` 的兼容表达待契约设计，不能任意挑一个覆盖其余起因或改写旧字段含义。
- 深度用于追溯与安全限制，不是证明任意持续输入下总工作量有限的依据。门控及处理条件见[信号补充](signals-supplement.md)。

## 5. 写入权限与反馈【MVP】

### 5.1 单写者

| 模块 | 负责写的数据 / 执行的反馈 |
|---|---|
| ① | 公共依赖、事件和消费标记机制；插件登记/权限及管理操作结果；只处理自身管理反馈 |
| ② | 外部来源原始数据 |
| ③ | 人物、地点、参考、归属关系及③的重判结果；纠正、确认、参考管理、地点创建、命名、范围重新归属 |
| ④ | 活动、规则、选规则结果、md 产物、建议及④的重判结果；提取、规则管理、审核/执行结果反馈 |
| ⑤ | 传播与调度记录；执行“重新判断其他相关记录”反馈 |
| ⑥ | 用户反馈及管理员管理反馈；执行外部动作后写反馈，不直接改④建议 |
| ⑦ | 模型调用系统记录，经①统一保存 |
| 插件 | 自己命名空间的获准类型及自己的重判结果记录，不写核心或其他插件的数据 |

公共记录由①机制管理，不代表①可以改写其他模块业务。③④及可重判插件的完成结果分别单写；不存在一个让所有业务模块任意改写的结果类型。

### 5.2 反馈流程

1. ⑥ 验证调用身份，将操作转为结构化、只追加反馈，写入①。
2. ① 发 `data_changed`，按授权订阅投递给职责所属模块；所属模块按当前状态处理。
3. 处理结果与消费标记按批次提交；相关业务变化携带反馈根源，⑥ 展示异步“处理中”和最终结果。

管理操作同样走反馈：⑥ 验证管理员，① 管理处理器消费自身管理反馈并调用内部管理逻辑，不 HTTP 自调；① 单写登记、权限及操作结果，⑥ 查询。提交和执行均复核可信授权，普通插件不得自授权限。已受理不等于生效，稳定请求标识和可恢复阶段支持幂等，资源就绪后才可启用；跨组件不承诺数据库/总线单事务。

反馈结构由相关模块共同同步契约。自然语言纠正【以后】先解释为建议、用户确认后再执行。

## 6. 归属模块（③）

### 6.1 新数据【MVP】

触发条件是声纹或 GPS 点尚无归属。若已是某对象参考，直接归该对象；否则与有参考的对象比较：人物匹配成功归已有对象，失败新建未命名人物并将该声纹设为首个参考，这是唯一一次自动设置参考；地点失败归全局唯一“未知地点”，它无参考且不参加匹配。

首次归属通常尚无下游；依赖是否存在由①查询，不把“新增”作为永不影响任何插件的假设。算法、阈值由负责人选择；③ 必须登记实际使用的候选对象及字段，如仅用参考匹配就登记参考字段，不读名字则不登记 `name`。

### 6.2 参考与用户确认【MVP】

- 人物声纹参考、地点 GPS 参考由用户维护，除首次自动建立人物参考外不自动增加。
- 纠正时从原对象参考移除该数据、加入新对象参考并改归属；确认时加入当前对象参考。一条原始数据最多是一个对象的参考，相关变化同批保持一致。
- 用户纠正或确认过的数据，任何重新归属均不得改变其归属结果。即使重判无变化，也刷新依赖并提交完成记录。

### 6.3 参考变化的历史门控【MVP】

管理参考时询问是否重新判断历史；纠正后不弹窗，提供“同时重新判断其他相关记录”按钮。按钮写反馈，携带纠正前后对象，由⑤查依赖再请③重判。纠正/确认伴随的参考修改默认不自动扫历史，但归属本身变化可传播给其下游。

用户选择后，曾实际用相关参考作为输入的归属均应被找到。新对象此前从未作为候选等无法由已有依赖定位的情况，用独立的“按时间范围重新归属声纹或 GPS 点”补足。首次命名、改名会触发 `name` 依赖者，只有参考字段依赖的归属不受其影响；具体写入门控见信号补充。

### 6.4 未命名人物、地点与以后功能

参考被全部移走的人物保留但不参与匹配；名下仍有声纹时提示“#N 还有 M 段声音，可能也是 X”，提供重判按钮；无声纹则整体替代。地点只能由用户在时间线或地图选择 GPS 点手动创建，这些点成为参考并改归属。

【以后】合并人物、自动建议创建地点、重判结果与用户判断不同时给出提示。MVP 中人物拆成多个对象时先通过参考和重新判断补救，不放松用户确认保护。

## 7. 活动提取模块（④）

### 7.1 触发与划分【MVP】

- 定时器在④内部；手动触发由⑥写反馈。两者都指定时间范围。
- 定时范围从上次成功定时提取结束到现在，扣除已成功提取的时间段（包括手动提取）；放弃的不算已提取。验收不漏段、不覆盖成功时间段。
- 前置检查范围内需归属的数据均已有归属，否则延后重试，超过上限放弃并提示用户。
- 活动划分、名称和描述**只用原始转写、时间、GPS、手机数据**，不读取推断人物、地点或归属。可使用原始转写里本来出现的名字；不猜人物地点 id。
- 纠正归属、人物地点改名不自动重划活动；用户明确重新提取才重新划分。原始输入与推断人物地点的使用边界不能因前置检查归属而混淆。

### 7.2 提取与选规则结果【MVP】

1. 划分活动后，④ 用自然语言规则的适用范围判断哪些当前规则适用。
2. 每活动保存一份版本化 `rule_selection`，④ 单写，登记实际输入和候选规则版本。
3. 按选中的规则生成 md 产物，并登记第 3.5 节要求的依赖；有可选动作时生成待审核建议。
4. 整天输入须可跑完；长数据的处理策略由负责人确定。

相关输入变化导致⑤请求重判 `rule_selection` 时，④ 重新查看**全部当前有效规则**（含新增、不含删除）：新选中则生成产物/建议；不再选中则整体替代相应自动产物和未审核建议；仍选中则不额外触发产物重算，产物按自己的依赖处理。

**产物不直接依赖 `rule_selection`。** 手动应用的产物不因自动规则选择不适用而撤销；若该产物因其他输入收到重判且其原规则已删除，则执行第 7.4 节的失效处理。规则集合新增、候选缺失及并发保护的具体方案列入验证计划，不在本文虚构现成接口。

### 7.3 手动重新提取【MVP】

用户明确重新提取时间范围时，旧活动和旧 md 产物整体替代，新活动用新 id。执行前提示“有 N 个活动带有你的修改，重新提取后这些修改将失效”。对应未审核建议按失效处理，已审核或已执行的建议不重做。

旧活动/产物可能有插件下游，⑤ 仍须检查并请求其所属方重判，不能假设本批核心对象替代后所有下游已经同步完成。【以后】识别活动延续、沿用 id 并迁移用户修改。

### 7.4 规则与重判【MVP】

- 规则用自然语言说明适用范围、提取内容、可选动作；条件是否匹配由模型判断。“只改这一次”保存为只适用于一个活动的规则，创建后立即提取。
- 新增、修改、删除规则本身不主动重算历史；用户可手动将规则应用到历史活动，跳过自动选择并追加产物。
- 历史产物被其他输入变化触发重判时，使用**同一规则 id 的当前版本**，带旧产物和变化原因，不固守产物最初的规则版本。额外发现的规则版本变化/删除必须记录为起因。
- 此时规则已删除或整体替代，产物及其未审核建议整体替代；已审核、已执行、已拒绝建议不动。不因单个产物的规则失效自动改用另一条规则。
- 验收：当规则版本也未变且输入变化不影响输出时，重判输出与旧版逐字相同；规则已变不能继续套用这个逐字不变前提。

### 7.5 纯 Markdown【MVP】

产物包含 id/版本、所属活动、规则 id/版本、自动选择或手动应用来源、Markdown 正文、生成方式与追溯上下文。正文直接写人物地点名字，不存特殊 id 引用标记，也不从正文反猜 id。

实际放进模型/计算输入的人物地点字段都登记依赖；首次命名和改名触发 `name` 依赖者重新判断。参考字段专用的归属不因名字变化重算。活动名称描述不读取推断对象，因而不随人物库改名自动改变。

### 7.6 外部动作建议与未知结果【MVP】

核心 MVP 提供写入日历（标题、起止时间、备注）和提醒事项（标题、截止时间、备注）。规则动作从这两种可用且获准的系统能力中选择；插件使用系统已有日历/提醒事项能力也必须经过建议→用户审核→执行，不得绕过审核。本轮不新增插件自定义动作类型或执行器机制。插件动作交接的所有权与 Schema 待契约设计，不允许插件直接写④建议。

- 流程：④生成建议 → ⑥展示并写审核反馈 → ④更新建议 → ⑥执行 → 写执行反馈 → ④更新状态。
- 建议记录源 md 产物及版本。产物有新版本时，只整体替代未审核建议并按新版本生成；已批准、执行中、结果未知、已执行、已拒绝均不当作未审核作废，不随产物变化重做。
- 审核确认的是动作，不是产物内容；md 产物照常依赖分析，因此可能与外部条目不同。已执行动作视为用户确认，不自动修改外部结果。
- 可靠外部幂等机制使用稳定动作标识；能查证成功就不重复，明确未执行才重试；**外部结果未知时停止自动重试并提示用户核对**。用户可确认已执行，或在明确重复风险后选择重试。
- 本地当前状态/消费标记不能消除“外部成功、回写前崩溃”的窗口，不承诺任意外部 exactly-once。允许为恢复保存必要外部标识，具体位置与格式待实施/契约设计，不能用禁止保存外部 id 阻断恢复。
- 【以后】更多核心动作类型、产物变化后提示用户同步已执行外部动作。

### 7.7 以后功能

问答按需补充（先查产物、不足再查转写）、补传数据检测、跨定时边界活动、录音结束等自动触发、直接修改活动边界/拆分/合并、直接编辑或删除产物仍为【以后】。字段级依赖已纳入 MVP；进一步把活动范围内全部归属粗依赖缩为只用到的归属，仍属以后，不在本轮放宽。

## 8. 依赖分析模块（⑤）【MVP】

### 8.1 调度与完成记录

1. 接收获准范围内的修改/整体替代通知，或执行“重新判断其他相关记录”反馈；按历史门控及规则编辑例外筛选。
2. 通过①找当前有效对象中过时的依赖，读取前后输入，保留所有起因；所属方和是否支持重判来自注册表，不增设第二个执行人字段。
3. 已知相关受影响上游可并行；下游必须等这些上游完成。尽量合并多原因为一次重判，但不作全局停顿，也不承诺持续输入下只重算一次。
4. 所属方查当前状态与输入，经⑦计算，向①同批提交业务变更、完整依赖刷新、消费标记（`MarkProcessed`）和自己的成功结果记录。无变化也完成该批次，只是不新增业务版本/事件。
5. ⑤ 通过①查询完成记录，MVP 使用轮询；不能只等修改事件，因为无变化也须释放等待。更新传播记录后继续下游。
6. 计算中有新输入到达，提交时①检查新鲜度；冲突后重读重算，不能提交一个已知过时结果冒充当前结果。

结果记录语义包括：请求 `event_id`、目标、变化/无变化/不适用/失败、前后版本、额外起因、根源/深度、时间、错误。**这些语义适用于③④及所有可重判插件**；准确新增类型和英文枚举待契约同步。⑦ 调用须携带重判请求 id 关联。

可重试错误先重试，耗尽或不可恢复才记失败；崩溃未交结果属于等待/超时，不是成功。失败、超时、停用导致下游等待受阻，保留旧结果并展示不可更新/过时，不假装最新。不适用须明确目标最终处置，不可用不是默认成功。

### 8.2 DAG、持续输入与替代

- ① 对**当前有效对象的最终依赖图**强制无直接/间接/自环；成环整批拒绝并给定位信息。历史边不永久禁止当前合法关系；批内与并发检查均须可靠。
- 支持任意有限层数的跨插件和插件内部链，不限制一两层。md 产物可以有下游，⑤ 不能将其写死为终点。
- 对一次有限工作集，在无新输入且重试有界时，沿 DAG 推进，最终完成或明确阻塞/失败；持续输入可持续产生新工作，不声称无限总任务也有限。
- 一条路径无下游、或结果未变且不再影响下游时停止；下游若另有起因仍可被触发。安全深度/次数等限额触发须记录并提示，不能当成功完成。
- 上游删除/整体替代由下游所属方重判，① 不级联删除。无法生成有效结果时明确不可用或整体替代；用户确认的归属保护不因此被推翻。

### 8.3 验收

受影响依赖不漏查；多原因可追溯；相关上游等待正确；无变化完成可释放等待；失败不伪成功；整条传播关联所有模型调用；并发新鲜度校验与无环检查有效；多层链在上述有限工作集条件下终止。

## 9. 大模型入口（⑦）【MVP】

基于 Octopus 已有接入部分独立为 docker 服务，后端对接反代平台。各模块和插件调用大模型都经过⑦，带调用方模块、`root_feedback_id`；重判调用另带请求 id。缺少调用方的调用拒绝，身份仍以可信凭据验证。

⑦ 单写调用系统记录，经①统一保存，不发事件；默认只保存统计/追踪 metadata，例如用途、用量、耗时及关联信息。提示词/响应正文仅显式按需开启；这不影响业务模块正常保存业务产物正文。正文保留期和作用域仍是待定可配置实施参数。

换模型、限流、重试在⑦统一处理。验收可按模块、根源统计用量，关联传播请求。逐次尝试粒度的详细日志仅为实施建议，未单独批准为强制精确粒度。

## 10. 动态插件【MVP】与检索【以后】

### 10.1 插件设计入口与核心约束

插件完整注册/生命周期/权限/历史处理定义统一维护在[动态插件 MVP](plugins-mvp.md)。本文只保留与核心架构衔接的约束：

- 管理员授权可信插件，独立进程运行，不提供代码沙箱隔离保证；动态持久注册命名空间、类型、所有权、重判能力、身份权限和消费者。最小范围含注册、启用、停用、凭据更换/撤销；不做市场、自动安装启动、热升级。
- 默认拒绝，按类型批准当前及历史读取；订阅独立授权且不得超过读取范围；依赖引用须有读权限。① 所有读、按 id、query、历史、依赖接口均过滤，不能只在 UI 隐藏；凭据不作为普通可读类型暴露。
- 不做逐字段/逐条 ACL；字段依赖不是权限系统。新增权限需重批，普通插件不自授权限。
- 插件经①读写、经⑦调用模型；只写自己的类型，可依赖获权核心、其他插件及自己的结果，服从当前对象 DAG；核心不能反向依赖插件。
- 停用阻止新访问和投递，不撤销已提交写入、不默认删数据；撤权阻止后续读取，保留旧结果并标示无法更新。保留部署应急阻断能力，不是日常绕过 UI 的管理入口。
- 首次启用只自动处理启用后的变化；历史范围补处理须用户显式选择。主动停用恢复提示漏过变化，由用户补或跳；意外断线/重启自动续处理。读历史上下文不等于获准历史批量生成。
- 补处理查当前状态而非盲目重放旧事件；跳过不把旧结果标新，可显示 stale。具体游标/snapshot 交接协议待实现设计。
- 插件文本输出采用纯 Markdown，不再要求特殊引用标记；通用插件结果浏览页和具体业务插件仍为以后，轻量管理页不是完整客户端。

### 10.2 检索索引模块（⑧）【以后】

⑧ 订阅获授权的产物新增、修改、整体替代事件，更新自己拥有的索引；不让核心依赖索引，外部 Agent 只读，修改只能走建议/反馈。确定性的切片向量化通过事件更新，不作为推断结果接收重判请求；不索引外部动作建议。

初稿验收：只有当前有效产物可检索，旧版或整体替代产物从当前索引移除；结果带产物 id/版本、活动 id/时间范围，可回①读完整产物；支持时间、人物、地点过滤。纯 Markdown 名字依赖在产物重判更新后触发索引更新，不依靠显示替换实现改名；具体索引、切片和关联元数据方案后续确定。

## 12. 端到端验收【MVP】

### 12.1 数据

判定使用模拟组会：事先确定说话人、时间、活动边界、待办、建议和地点标准答案，用于回归与演示。真实数据仅用于经同意的连续一天可靠性检查、调参和辅助标注，不作为标准答案或入库 fixtures；另有规则应该/不应该触发测试集。

### 12.2 核心流程

| 步骤 | 内容 | 模块 |
|---|---|---|
| 1 | 组会录音、GPS 入库 | ② |
| 2 | 声纹归人物、GPS 归地点 | ③ |
| 3 | 定时划分活动，保存规则选择，生成纯 Markdown 和提醒建议 | ④ |
| 4 | 通过 API/验收工具看到时间线、产物和建议 | ⑥ |
| 5 | 纠正“A 不是甲，是乙” | ⑥→③ |
| 6 | 待办负责人更新；未审核建议重生成；规则版本未变且不受影响的产物逐字不变；相关上游先完成 | ③④⑤ |
| 7 | 审核并执行，正常结果与未知结果均按恢复规则处理 | ⑥→④ |
| 8 | 查询全部起因、完成/阻塞状态及关联模型调用 | ⑤⑦ |

### 12.3 新增重点验收

- 字段缺失/null、数组顺序、重复字段、空 fields、A→B→A、整体替代、依赖漏登与显式空集。
- R6 历史 status 不变，终止版本事件版本号准确，重复终止幂等且终止后拒写。
- 规则只编辑不扫历史；其他输入触发采用最新规则；失效不换规则；选择结果改变与产物独立依赖；手动产物保护。
- 改名/首次命名触发名字依赖而不触发纯参考归属；活动不读取推断人物地点。
- ③④插件均有无变化完成记录；崩溃/超时不报成功；多原因、上游等待、并发新鲜度及多层 DAG 成环拒绝。
- ①消费管理反馈、异步生效、动态发现和权限过滤；初次启用、主动停用与意外断线采用不同历史处理语义。
- 外部成功回写前崩溃、明确未执行、结果未知、用户确认/风险重试；⑦默认无正文日志且业务正文正常保存。

这些是目标验收，不是本轮已经通过的测试声明。
