# 术语表（中 → 代码标识）

文档用中文，代码标识用 `snake_case`；类名用对应的 `PascalCase`（如 `ActionSuggestion`）。**同一个概念只用一个标识，但术语确认不等于契约已实现。**

本轮按项目负责人逐项确认及同步授权更新，依据见[确认索引](decisions/mvp-confirmed-decisions.md)、[设计 v1.2](design/design-v1.2.md)、[插件 MVP](design/plugins-mvp.md)和[信号补充](design/signals-supplement.md)。原 review 字段仅为历史审核记录，不是本次正文已人工新审的证明。

- 下表保留原有公共标识；标为草案、暂拟或历史的条目不作为已冻结的新契约。
- `rule_selection`、`fields` 是本轮已讨论术语，准确结构/位置仍需契约设计，不能据此宣称现有 `contracts/` 已支持。
- 其他新增英文类型、字段或状态名均暂拟、待契约冻结；未必要定名的概念先用中文说明，不制造第二套 API。修改 Schema 仍须①负责人与 I 审核，只加不删、不改义，本次不修改 Schema。

## 模块

## 版本与状态

| 中文 | 标识或含义 |
|---|---|
| 版本号 | `version`（整数，从 1 开始；原始数据固定为 1，不使用版本 null） |
| 当前版本 | 同一对象的最大版本；“current”仅为说明性称呼，不新增状态枚举 |
| 历史版本 | 比最大版本旧的记录，内容和写入时 `status` 均不可变 |
| 活跃状态 | `active` 是版本写入时状态；旧版本仍为 `active` 不表示它现在是当前版本 |
| 整体替代 / 终止版本 | 追加内容同 n、`status = superseded` 的 n+1 版本，使整个对象终止；不是修改旧版本 |
| 新增 / 修改 / 整体替代事件操作 | `created` / `updated` / `superseded`；操作名与版本内状态是不同概念 |

整体替代事件的新版本为 n+1、旧版本为 n；终止后拒绝继续更新，重复替代不新增版本或事件。默认查询排除已整体替代对象，按 id 和历史查询仍可读。普通更新不把旧版本回写成 `superseded`，也不额外发旧版的替代事件。

外部动作建议的原有状态标识（准确契约仍以 contracts 为准）：

| 中文 | 标识 |
|---|---|
| 待审核 | `pending` |
| 已通过 | `approved` |
| 已拒绝 | `rejected` |
| 已执行 | `executed` |
| 执行失败 | `failed` |
| 已被替代 | `superseded` |

新增“执行中”“结果未知”的业务含义已确认，英文枚举暂不定名，待契约冻结。已批准、执行中、未知、已执行、已拒绝都不能当作未审核建议作废；产物变化不会自动重做这些外部动作。

“结果未知”不等于“明确执行失败/未执行”：可靠幂等或可查证成功则不重复执行，明确未执行才可重试；未知须停止自动重试、提示用户核对，允许确认已执行或明确要求重试并提示重复风险。不承诺任意外部 exactly-once，必要外部恢复标识的存储方案待设计，不再硬性禁止记录外部 id。状态由④通过⑥执行反馈更新，插件不直接写④数据。

核心外部动作类型仍为写入日历 `calendar_event`、写入提醒事项 `reminder`。插件使用系统已有日历/提醒事项能力也必须走建议→审核→执行，插件交接的类型/格式另待契约设计。

## 事件与依赖分析

| 中文 | 标识 |
|---|---|
| 总线 | `bus` |
| 「数据库被修改」 | `DataChanged`，`event_type = "data_changed"` |
| 「请求重新判断」 | `ReevaluationRequested`，`event_type = "reevaluation_requested"` |
| 根源反馈 id | `root_feedback_id`；系统发起时为字面量 `"system"` |
| 依赖分析深度 | `depth` |
| 不处理历史 | `skip_history` |
| 起因 | `cause` |
| 可读的修改描述 | `change_description` |
| 依赖分析 | `dependency_analysis` |
| 依赖登记 | `dependency_record` |
| 传播记录 | `propagation_record` |
| 登记表（数据类型 → 所属模块及是否支持重判） | `handler_registry`（沿用术语；实际登记/权限结构待冻结，不代表现有契约已支持动态发现） |
| 重新判断 | `reevaluate` |
| 字段级依赖选择 | `fields`（已讨论术语，可选；接口准确位置待冻结） |
| 强制完整依赖声明 | `requires_dependencies`（暂拟字段名，待契约冻结） |

**字段级依赖**：缺省 `fields` 按全对象版本判断过时；给出时按所选 `payload` 顶层字段的完整 JSON 值比较登记版本与当前版本。拒绝 `[]`，字段名去重排序；缺失与 null 不同，数组顺序有意义；A→B→A 当前可不再过时但已发请求不自动撤回；对象整体替代始终过时。字段依赖不是字段级权限 ACL。

**强制完整登记**：声明强制依赖的类型，新建/更新/无变化 Update 都同批登记全部实际依赖，未登记拒整批，不自动继承；显式空集表示真无输入依赖。整体替代免新登记、历史保留。①验证存在、引用、新鲜度与权限，业务方负责真实完整。

**重新判断结果系统记录**：③④及可重判插件各写自己拥有的类型，不由⑤代写；具体类型和字段名待契约冻结。记录关联请求 `event_id`、目标、结果、前后版本、额外起因、根源、深度、时间及错误。结果包含有变化、无变化、不适用、失败等含义；若使用 `changed` / `unchanged` 英文状态，它们也只是暂拟名，不宣称现有 Schema 已定名。成功结果与业务写入、依赖刷新、`MarkProcessed` 同批；无变化仍须交结果和依赖。可重试错误先重试，耗尽或不可恢复才失败；崩溃无结果是等待/超时，不能算成功。⑤在 MVP 轮询记录推进，不新增第三事件。

**多起因与阻塞**：`cause` 和 `root_feedback_id` 继续保留原含义，多起因兼容结构待冻结；相关上游可并行，下游等完成，失败/超时/停用须明确等待或受阻并保留旧结果，不能冒充成功。不适用或不可用不自动等同成功。多层调度和终止边界见[工作分解](design/work-breakdown-v1.2.md)。

## 提取与规则

| 中文 | 标识 |
|---|---|
| 定时提取 / 手动提取 | `scheduled_extraction` / `manual_extraction` |
| 提取记录 | `extraction_run` |
| 适用范围 | `scope` |
| 提取内容 | `instruction` |
| 可选动作 | `actions` |
| 只改这一次的提取 | `one_off`（规则的一种，绑定单个活动） |
| 纯 Markdown 正文 | 直接写人物/地点名字；不从正文猜 id，实际计算输入单独登记依赖 |
| 引用标记【历史格式，非当前要求】 | `[[person:<id>]]`、`[[place:<id>]]`，只用于辨认旧文档，不再要求生成或显示时替换 |

规则选择结果由④维护，登记实际输入与候选规则版本；被相关输入变化触发后查看全部当前有效规则，包含新增、不含删除。新选中生成、不再选中整体替代相应自动产物和未审核建议、仍选中不额外重算产物；产物不直接依赖选择结果，手动应用产物不因自动不适用而撤销。

规则修改/删除本身不主动重算历史。其他输入触发历史产物重判时用原规则当前版本；原规则删除/整体替代则替代该产物及未审核建议，不自动改用其他规则，记录额外规则起因，已审核/执行/拒绝建议不动。逐字不变验收以原规则版本也未变为前提。

产物保留活动范围内全部归属的粗粒度依赖，加实际用到的人物/地点字段；首次命名/改名使名字依赖者重判，不影响只依赖参考的归属。活动划分及名称/描述仅用原始转写、时间、GPS、手机信息，不读推断人物地点；原始转写出现的名字可用，纠正归属不自动重新划分活动。

## 动态插件与管理（MVP）

| 中文概念 | 含义与契约边界 |
|---|---|
| 可信插件 | 管理员授权的独立进程模块，动态持久登记并使用①SDK/⑦；不是不可信代码沙箱，也不是插件市场/自动安装启动/热升级 |
| 命名空间 / 所属模块 | 只写自己业务数据；所属方同时是重判执行方；准确字段名待冻结，无第二执行人字段 |
| 动态登记 | 核心内置配置加动态持久登记；①⑤发现插件无需改业务代码或重启，不等于仅在启动时读配置 |
| 管理受理与生效 | 稳定请求 id、幂等可恢复阶段，提交/执行均复核授权；受理不等于生效，就绪才启用；英文状态枚举待冻结 |
| 类型权限 | 默认拒绝，按类型批准读当前/历史；订阅独立批准且不超读范围，依赖引用需读权限；所有读/id/query/依赖接口过滤，凭据不作普通类型暴露 |
| 停用 / 撤权 | 阻止后续访问/投递，不撤销已提交写入、不默认删数据；旧结果保留并标无法更新，恢复补处理由用户选择 |
| 首次启用 | 只自动处理启用后变化；历史范围生成要显式授权，读历史上下文不等于批量生成授权 |
| 恢复 / 补处理 | 主动停用恢复提示遗漏，由用户补或跳；意外断线重启自动续处理；补处理查当前状态，跳过不把旧结果标新；游标/snapshot 交接待实施设计 |
| 多层无环 | MVP 支持跨插件、插件内部多层；核心不能依赖插件；①按当前有效对象最终依赖图拒绝直接/间接自环并整批拒绝定位，历史边不永久禁止当前合法图 |
| 传播结束 | 无下游或结果不变时结束相应路径，其他起因仍可触发；有限工作集且无新输入时终止或明确阻塞/失败，不能把安全限额当成功 |
| 插件管理轻量页面 | ⑥必须交付的 MVP 客户端例外；其余客户端仍不强制，原八步可由 API/测试客户端验收 |

本表中文概念不是新增字段清单。权限、管理结果、可重判声明及各系统记录的英文类型/状态暂不定名，等待统一契约冻结；详见[插件 MVP](design/plugins-mvp.md)。

## 大模型调用记录

⑦单写调用系统记录，经①统一保存，不发事件。默认仅保存统计与追踪 metadata（调用模块、根源、用途、用量、耗时及重判请求关联）；提示词/回复正文仅显式按需开启，不影响业务产物正文正常保存。具体记录类型、请求关联字段待契约冻结。

逐次尝试的日志粒度只是实施建议，未作为本轮独立批准项；正文保留期限和作用域尚待实施参数设计，不在术语表虚构定稿值。

## 术语辨析与待冻结项

- 「活动」用 `activity`，避免与总线「事件」`event` 混淆。
- 当前/历史是版本关系，整体替代是对象终止；不能因历史版本仍为 `active` 就把它当当前。
- 字段依赖比较不是逐字段权限控制；类型读取历史权限不是批量历史生成授权。
- 已确认的行为与未冻结的类型/字段是两回事：`fields` 位置、强制依赖声明、管理与权限记录、插件建议/执行反馈交接、重判结果/请求关联、多起因兼容均需契约设计。本表不宣称现有 contracts 已全部支持。
