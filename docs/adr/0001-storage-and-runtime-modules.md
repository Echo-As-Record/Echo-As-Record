# ADR-0001：独立存储服务与动态模块基础设施

## 状态与授权

已采纳的目标选型。来源为本轮逐项讨论：负责人认可独立①、PostgreSQL与同库多schema；对总线授权采用助手建议的NATS JetStream+Outbox；随后明确将运行时插件和多层无环依赖纳入MVP，并要求同步文档。见[决策索引](../decisions/mvp-confirmed-decisions.md)。

这不是部署完成记录，也不替代后续契约审核；没有新填或代填人工 reviewed 字段。

## 背景

原仓库已有公共Schema、同步StorageClient及MemoryStorage，但无持久化服务、总线部署或动态模块管理。目标需要统一执行权限、版本、内容比较、依赖、事务和可靠事件规则，并允许运行中接入获准插件。

## 决定

1. **①独立服务，SDK是客户端。** 业务模块及插件不直连数据库；身份从可信凭据绑定，不能信任自报模块名。保留StorageClient兼容目标及内存开发测试路径，新增能力通过契约演进明确，不承诺现有所有方法已能无改动映射远程协议。
2. **PostgreSQL同库多schema。** 每模块拥有逻辑空间，内部可多表；依赖索引、Outbox、消费标记等公共设施由①管理。schema不是天然权限边界；访问与所有权由服务及数据库权限共同落实。表结构、索引、迁移和数据库版本另作实施设计。
3. **批次内统一事务。** 业务计算/模型调用在事务外；业务写入、依赖、完成记录、消费标记和待发事件按批次原子提交。输入过时、权限冲突、成环或缺依赖等拒绝整批。
4. **NATS JetStream + Outbox/Relay。** 数据与待发事件先在数据库事务提交，再由Relay投递；允许重复、不允许静默丢失，消费方以状态和原子标记幂等。需要持久消费、失败重试、可检查的死信/重放与恢复能力，不能把这些全部当作总线自动提供的业务保证。
5. **动态持久注册。** 核心内置定义加插件登记；类型所属方就是重判方，另声明重判能力和依赖要求。①⑤运行中发现变更，不通过改代码/重启接入每个插件。
6. **管理仍走反馈。** ⑥管理员页面写管理反馈；①消费其反馈、执行内部逻辑、写系统结果供⑥查，不HTTP自调、不增第三事件。数据库/总线/消费者/授权配置跨组件采用可恢复阶段，不承诺一个跨系统事务。

## 取舍

- 相比共享库直连数据库，独立服务集中规则与身份边界，但增加网络协议、超时、重试、服务可用性和运维工作。
- 相比独立数据库，单库保留跨命名空间批次事务，减少MVP协调成本；模块仍有逻辑所有权，不能把单库理解成任意跨写。
- 相比仅内存通知，可靠总线与Outbox增加组件、日志和恢复流程；明确至少一次与幂等，不对所有外部副作用承诺exactly-once。
- 动态插件扩大①⑤⑥/I工作量。MVP只运行可信独立进程，不构建市场、自动代码执行或沙箱。

## 验证与未定实施参数

验证身份伪造/越权、同批回滚、实际并发、Relay提交后崩溃和发送确认丢失、消费重投、动态启停与撤权、多层DAG以及总线故障下应急阻断。详见[工作分解](../design/work-breakdown-v1.2.md)和[实施计划](../../ai-docs/plans/mvp-implementation.md)。

HTTP或其他服务协议、快照令牌、订阅连接方式、主题与消费者命名、死信实现、软件具体版本、保留期和重试次数未在本轮冻结；工程方案须遵守已采纳目标，不能伪装成用户已批准的具体数值。
