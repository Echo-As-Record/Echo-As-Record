# 人物记忆扩展

本包是实验性插件，使用 `habit` 身份通过① SDK 读写；③仍是人物归属的唯一写者。跨模块方案处于[提案](../../docs/proposals/person-memory.md)状态。所有测试使用合成数据，未在真实 EAR 实例部署。

## 已实现

- 事件消费者 `PersonMemoryWorker` 订阅转写、活动、归属和日桶变化。重算受影响的日统计及活动索引，日桶变化再计算周/月桶；纠正归属时会清空旧人物对应统计。重复事件使用原子处理标记；支持⑤重判完成。远程写入通过③的持久日志事务组件恢复未知结果。
- 按人物和 UTC 时间建立日、周、月统计；默认使用 `jieba 0.42.1`、关闭 HMM。填充词和表达候选只是文本匹配，片段时长不等于纯发声时长，不是已验证的习惯结论。
- 活动观察包含归属与未知片段、参与者共同出现及相邻轮次候选。相邻轮次不是对话证明，共现不是关系证明。`conditional_profile` 可按另一人在场和调用方提供的活动集合计算统计，不代表言语是对该人说的。活动与查询窗口重叠即可纳入，统计覆盖活动完整范围。
- 每个活动有有界压缩索引、来源片段及版本依赖；保留 EAR 原始转写/音频引用。`search_episodes` 提供原文、摘要、混合词法检索以及历史 `as_of`，附证据与新鲜度；摘要不能证明精确原话。当前新鲜度只检查已登记依赖，无法单独证明新输入已被消费者处理完毕。
- `recognition_context` 返回目标片段之前同一录音中的上下文；`confirmed_candidates` 是离线词项匹配研究基线，仅使用目标之前、不同录音且截至 `as_of` 已由用户保护的归属样本，返回证据而不决定身份。`address_hints` 可利用调用方提供的别名和紧邻上一轮的明确称呼提出候选，保留原句证据；被称呼的人也可能并非实际回应者。上述方法未接入③或声纹模型，准确率未知。

入口 `PersonMemoryService` 提供显式重建及只读查询；其 `since` 作用于构建桶及事件索引，而 `activity`、`social_window`、`conditional_profile`、识别查询按调用参数读取已有数据，不自动受该截止时间限制。

## 使用和限制

1. 构造存储时用 `extend_registry(DEFAULT_REGISTRY)` 注册插件类型，并为 `habit` 配置需要的读取权限。远程注册、权限与⑤的集成需要负责人对齐；这不是自动安装。
2. 以 UTC 时间保存一次启用时间，创建 `PersonMemoryWorker(client, active_since=..., journal=...)` 并调用 `subscribe()`；宿主负责启动、驱动事件消费、停止和重启。远程客户端必须提供持久 `CommitJournal` 并在重启后使用同一个日志与启用时间。订阅不自动扫描历史；启用前数据只有通过明确的历史重建流程处理。
3. 全部桶与事件索引写入必须由单写者串行执行，包括手动重建。不可把 `PersonMemoryService` 的手动重建当成具备远程未知写入结果恢复能力的作业；远程批处理需另做持久事务封装。启用时间和既有数据范围不一致会报错，避免静默合并。
4. 事件和片段有批量/检索上限，超限报错而非静默截断；宿主应监控失败和积压。消费者订阅不保证补齐启动前错过的变更，需要显式协调恢复或重建。未实现常驻进程、HTTP API、生产部署或实时性保证。
5. 统计 schema 2 与旧单字分词 schema 不可混合；如已有旧桶须在隔离环境规划并执行重建，不能直接合并。跨日片段计入起始日。

未实现自动删除、授权管理或真实样本验证。不要把合成数据效果当作实际识别性能。

## 本地合成验证

在仓库根目录准备好项目的 Python/uv 环境后执行：

```bash
uv sync --frozen
uv run --frozen pytest -q services/habit
```

测试包括归属更正自动传播、重复事件、重判完成、相似事件检索、时间截止与识别参考样本泄漏检查；无真实录音。
