# v1.2 第一轮迁移与 mock 联调

## 本轮实现

- 产物/动作文本改为纯 Markdown，拒绝旧人物地点引用标记；模型人物地点输入只传 name，不传参考库。活动划分仍只读原始证据。
- 重判读取同一规则当前版本，记录额外规则变化原因；规则停用/删除则替代产物与待审核建议，保留已审核建议。编辑规则本身不重算历史。
- 规则升级即使正文相同，也更新产物规则版本与依赖；要求完整模型结果。动作参数改变但正文不变，也更新产物及未审核建议。
- 人物地点作为计算输入登记依赖；①尚不支持字段范围，暂按全对象版本保守登记，因此参考等非 name 字段变化可能导致多余重判。这是明确的兼容差距，不是字段依赖已经完成。
- extraction_run 保留原请求 cause、额外原因、前后版本、完成时间；成功业务提交同批追加独立 `extraction.completed` 消费标记。受理标记 `extraction.jobs` 仍只表示任务已持久接单，不能当完成。
- 重判模型请求携带 request_id；默认诊断记录不存输入输出正文，保留失败尝试及重试追踪，显式开关才记录正文。不是⑦统一调用记录的替代。

## mock 联调范围

`ear-extraction-mock-integration` 使用真实④逻辑、① SDK/MemoryStorage、重复事件投递、实际 loopback HTTP 请求；②③⑤⑥⑦均为明确标识的模拟参与方。

场景：合成转写、GPS、手机信息 → 两条规则 → 活动、待办及笔记 → 纠正归属与参考 → ⑤查过时依赖并发请求 → 待办改变/笔记不变 → ⑤轮询两个完成结果 → 替代待审核建议 → 审核 → ⑥模拟执行并写反馈 → ④保存回执。

另覆盖 HTTP 503 后自动重试、无效输出后显式重试、失败无部分落库、请求归因、默认无正文日志、重复投递下的单次模拟动作。执行器使用内存字典模拟支持稳定幂等键的外部系统；没有验证任意真实外部系统 exactly-once、未知结果或跨进程恢复。

迁移回归覆盖当前规则、规则失效、审核建议保护、改名重判、人物并发更新拒绝旧结果、动作日期单独变化、正文采集开关、失败尝试记录和完成标记。

旧产物不会批量自动迁移。重新提取或收到合法重判时写入新格式；模型返回 unchanged 但旧正文仍含引用标记时明确失败，保留旧产物。需要人工选择范围发起迁移，不用升级行为绕过历史门控。

本轮不包含真实模型、真实②③数据、生产⑤传播调度、⑥手机执行、①持久化的集成，亦未实现上述缺口所依赖的完整 v1.2 功能。
