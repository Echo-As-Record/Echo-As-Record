# 离线重提取元数据预检

`ear_extraction.reextract_preflight.plan_reextract_preflight(PreflightInput(...))` 逐个保留精确采集区间，划出可复核的分组和旧版本的候选替代范围。结果始终是 `status="preview_only"`。它不读 Storage、证据或调用审计，不连网关、不产生写入操作，也不能作为模型发送授权。

## 私有输入

- `scope` 是不超过 32 小时的 UTC 半开区间。所有区间非空，字符串用带秒的 RFC 3339 `Z` 格式，最多六位小数（也接受有零 UTC 偏移的 `datetime`）。采集和隔离区间须完整落在 `scope` 内；应选足边界，不裁剪原始采集以适配范围。
- `captures` 最多 512 项，只传已独立核验且明确选中的真实采集，每项用完整 `audio_ref` 时间边界和 Storage UUIDv7。按时间顺序排列，不能重叠或重复。调用方排除合成、未核验和未选中的采集；省略只表示无可用覆盖，不证明时间段内没有活动。若省略的范围仍须隔离，应显式列入 `holds`。
- `holds` 最多 512 项，包含调用方已核实的全部隔离或结果未明区间。按 `(start, end)` 严格升序；允许不同区间重叠。哪怕只交叠一点，也隔离**整段**受影响的采集。边界相接不算交叠。
- `targets` 最多 1,000 项，须是同一份完整快照中的当前有效活动及其所有有效产物和选规则结果。保留未裁剪的对象时间（可伸出 `scope`）、UUIDv7 和严格正整数版本，子项提供真实 `activity_id`，按 `(start, end, id)` 升序。孤立、歧义链接或重复 ID（包括同时提供同 ID 的多个版本）拒绝整份输入；一个活动不得有多份有效选规则结果。缺漏快照无法由本模块发现。
- 每个目标必须明确标记 `protection` 为 `automatic`、`manual_or_edited` 或 `unknown`。只有确认不是手工且未经编辑时才填 `automatic`；活动和产物的版本大于 1 时仍按受保护处理，不把选规则结果的正常更新当作用户编辑。每个活动还必须汇总 `action_safety`：`clear` 只用于已核实无活动关联动作，或活动所关联产物（含已终止产物）的有效动作均已执行或拒绝；待审、已批准、执行中、失败或结果未知用 `protected_action`，无法核实用 `unknown`，两者分别记录阻塞原因。动作本身永不进入版本清单。不要把旧 API 的 `versions` 作为完整输入，它不包含选规则结果或完整动作保护信息。

## 如何解读结果

- 只有相接的未隔离采集归入同一 `components` 项，原采集仍逐项保留。`coverage_issues` 把其余时间分为 `gap` 和 `hold`，同时输出原隔离区间和整段被隔离的采集。该分组只为复核，不表示场次连续、换场、静默或用户参与；参与、观看/收听、背景播放及 `unknown` 仍由[离线时间线边界预览](timeline-preview.md)区分。本模块不实现或调用这一步，也无法评估转写覆盖。
- 旧活动及其关联对象作为一组复核。任何对象跨组件、触及有效隔离区间、未完整落在单一组件、时间与所链接活动不匹配或受保护，全组保留并注明原因。该组碰到的组件仍可复核，但不生成替代范围；即使同组件有其他可用旧对象，也不会输出绕过它的部分清单。独立组件不受影响。没有旧目标不产生替代范围，也不等于允许新建。
- `replacement_scopes` 各自覆盖一个完整组件，`pins` 记录旧活动、产物和选规则结果的 `data_type`、`id`、`expected_version`，不是退役指令。`retained_targets` 单列保留对象及原因。结果含私有时间与对象 ID，不进日志、Git 或模型请求。预检不验证业务依赖、上游完整性或版本是否仍是最新；重新投影可对比旧清单，不得把差异自动变基成新确认。若后续另行批准写入，也必须由所属方重新核查范围、全量版本和证据、动作与依赖，再走正常授权流程。现有课堂路径仍要求完整逐行划分；不要把本结果提交给任何旧重提取命令。
