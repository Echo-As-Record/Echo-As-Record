# 有界自动时间线划分：宿主接线和复核

[行为边界](../README.md#宿主可选有界自动时间线划分transcript_automatic_timeline)。此处说明源码能力，不是发布、发送、读取真实证据或替换旧数据的授权；没有真实模型或真实导入验收。

## 私有精确范围

- 在现有 `0600` worker JSON 中，沿用 `transcript_only: true`、`transcript_course_sessions: true`、全局已启用的 `transcript_summary_rule_id`（无动作）、原 `transcript_windows`、现有 ①/⑦配置和单宿主锁。`schedule` 不可用。`transcript_course_reextract` 不开启；不得提供旧草稿、已核实前序列表或 schema 丢弃证明。
- `transcript_automatic_timeline` 值是[可信预检输入](reextract-preflight.md)的闭合对象 `scope/captures/holds/targets`，不是转写、模型回复、预检统计或公开 API 的版本图。完整原始采集必须是无留置对象、无 gap/hold 的单个连续组件，且首尾与完整允许窗清单精确匹配；允许窗也必须相接（计算窗不一定是实际采集窗）。没有旧目标确实填 `targets: []`，不能将有疑点或受保护的旧家族从预检投影删除。它和逐输入 scope SHA-256 是宿主信任边界，不是独立的真实采集证明。
- [活动时长门槛](../README.md#自动划分的活动时长门槛)的生效值也进入新准入 SHA-256，包括默认值；升级前或旧门槛下已入队的自动时间线任务不能按新配置执行。重建 v1 前序证明时仍使用原前缀和原载荷，不加入门槛。调用和旧运行元数据指纹的格式不变。
- 空目标组件走现有手动 `extract`，不带 `preview`；非空组件走 `reextract`，带现有公开预览的完整 `versions`。保存于任务的配置指纹阻止已接纳的旧反馈在关停或更换组件设定后按另一模式运行。v2 使用新指纹前缀，旧版已接收但未发送的反馈也不会自动换用 v2。覆盖多个组件时，各自独立预检和人工发起；不合并间隔、未明确授权的范围或留置采集。人工复核稿写入仍是旧交接路径；空目标的人工复核稿见文末计划，不应伪造旧 pin。

## 跨缺口替代旧活动家族（可选）

行为见[模块入口](../README.md#私有可选跨已知缺口替代旧活动家族)。在原私有 `0600` 配置中另填 `transcript_automatic_timeline_gaps`：按时间排序的非空 UTC 半开区间数组（最多 23 项），须与完整相接采集组件之间的补集逐项精确相同，不允许前后留白或任何 `holds`。保留 `transcript_automatic_timeline.captures` 的已独立核验的原始 `audio_ref` ID／时间（最多 512 项）；不要把计算读窗的范围或 ID 写回采集投影。`transcript_windows` 必须是 `pack_session_windows(tuple(c.interval for c in plan.components))` 的结果，其中 `plan` 来自 `plan_reextract_preflight`。这个离线 helper 每组件从其起点分 15 分钟窗及余数，不切分转写、不越过组件、不提升 24 窗／120 次调用上限；不能装下则拒绝整笔。即使某一跨缝转写同时命中两个查询，它也只按原始时界进入一次审阅序列；真实录音接缝仍需原话锚点。转写的 `audio_ref_id` 必须标识配置中的真实采集，且转写时界必须落在其内部；缺失、不匹配或越界阻止发送。没有额外读取 `audio_ref` 正文、路径、音频或其权限；宿主仍负责核实采集投影的真实性和完整性。

- 私有预检仍列出完整的当前活动、产物、`rule_selection` 及保护信息。原预检仍为 `preview_only`；此模式只解除跨组件这个结构阻塞，不解除动作、人工编辑、可疑链接、孤立/遗漏对象和范围检查。整个范围及配置（含采集 provenance、计算窗、gap、版本钉、固定规则）使用独立准入指纹。旧反馈不会继承此权限。不支持 `extract`、定时或课堂草稿；前序钉仅支持下节的 `all_calls_saved_success_no_business_write`。继续使用公开 `preview.versions`，不新增反馈或公共契约字段。
- 预检后和每次发送前重核整段前序与现行家族，提交前再查。对原始转写使用范围计数及类型修订守护，对未改写的动作集合用类型修订守护关闭末次保护检查后的竞态，对旧对象及当前运行用 CAS。守护与旧终止版、新活动／产物／选择、依赖和完成记录同批。活动、关联子对象和重叠任务的**集合**检查仍依赖既有④单宿主写锁；现有 `AssertTypeRevision` 不能在同批修改所断言类型，不能用此功能部署多个④写者。
- 仅限自动时间线之下；缺口不是留置、无语音区间或未分类行。声明的真实缺口只单列计数，不是证据或已知结束。其他不确定覆盖与旧范围相交仍阻止替代。新片段说明与笔记指令均不把边界当开场、收场或跨缺口延续。旧 Markdown 和审阅内容不发送给生成；生成只见单个新片段的证据。
- 合成测试：`UV_OFFLINE=1 uv run --no-sync pytest -q tests/test_mvp_worker.py -k automatic_timeline_gapped`；25 条采集／两组件，含原 v1 家族与有完整证明的更大失败批次同时存在的用例，另有缺口诱饵、活动／产物证据遗漏、同时或晚到的未知任务、动作竞态及旧版本 CAS。没有生产或真实数据验收。

## 连续采集中的已核实 ASR 缺口（可选）

[行为边界](../README.md#私有可选连续采集中的已核实-asr-缺口)。私有 `0600` JSON 中的 `transcript_automatic_timeline_asr_gaps` 为 `{start, end}` 对象数组，默认省略或 `[]`（原行为和准入 SHA-256 不变）。非空时最多 64 项：带秒的 UTC `Z`（最多六位小数），非空半开区间，按时间升序、互不重叠，完整位于精确范围内，并保留部分覆盖。空目标、无 hold、连续完整允许窗及单个完整物理采集组件等门控照旧；不得同时填写 `transcript_automatic_timeline_gaps` 或任何前序 pin。非空数组以单独字段进入私有范围 SHA-256，新增、移除或改变时不得沿用已入队反馈。

宿主须在运行前核对导入清单、真实 `audio_ref` 的完整边界及缺失时段：配置是独立审核后的声明，worker 不额外读取音频或 `audio_ref`，也不依据文本猜测缺口。每行 `audio_ref_id` 须匹配配置中原样保留的采集，且行不得越出该采集或相交于任一 ASR 缺口。允许物理查询窗没有行；零行或没有可靠活动仍阻塞。单个计算核心区可在缺口两侧各有独立审阅视图，缺口本身不发送、不产生接续或换场证明；片段生成只使用各自证据。审计 `declared_asr_gap_intervals` 只记已声明的项数；其他不可用覆盖仍单独计数。

整段（含缺口）在发送前和提交前核对旧活动／产物／选规则结果（含可查询的已终止版本）、重叠任务及原始数据守护。晚到行使原计划失效，不自动重算或重发。本设置不续跑旧任务、不处理旧发送回执、不改导入或留存；不能代替独立核对旧源。合成回归：`UV_OFFLINE=1 uv run --no-sync pytest -q tests/test_mvp_worker.py -k automatic_timeline_asr_gaps`。

## 可选：核实旧任务未写入后，以新反馈处理精确范围

仅为显式授权的完整精确范围配置私有 `transcript_automatic_timeline_prewrite_pins`，默认省略或 `[]`；无 pin 时不会豁免相交的未核清旧任务。空组件（`targets: []`）走 `extract`，范围内不得有现行或已终止的活动／产物／规则选择结果。非空范围走 `reextract`（可声明真实缺口）；此处验证前序旧任务未写入，**不**要求替代范围没有业务对象。不得与 v1 试验钉混用，也不接纳隔离区间或需保留的家族。

**填配置之前先在宿主之外独立核实。** 对每个阻塞该组件且相交的旧 `extraction_run`，按确切 run UUID、原边界、持久 intent 的 call UUID／用途／请求指纹核对整笔旧任务，而非只核对与新选区重叠的几条调用。确认每次调用在 ⑦ 已保存为 `success`、没有未追踪或在途发送、没有缺失／pending 的审计，且 ① 无该旧任务产生的任何原业务写入（含历史及终止版本）；只看新范围当前是空的、看失败标签、看总数为零，均不构成证明。原批次可以跨出新范围，但只要任何一部分不确定，都不能为其任何子范围签发 pin。保留可供独立复核的只读审计凭据；不要用 `reconcile` 补写 pending 的 Gateway audit 来制作证明，也不要读取或重放请求／回复正文。配置是可信宿主对独立证据的声明，worker 不自行证明负面写入事实，也不请求审计修复、增加 Storage 权限或联系旧 provider。

每项固定形状：

| 字段 | 填写内容 |
|---|---|
| `run_id` | 旧 `extraction_run` 的确切 UUIDv7（不是反馈、活动或 call ID）。 |
| `scope` | 新 `transcript_automatic_timeline.scope` 的精确 `start`/`end`（UTC `Z`）；为每个新组件单独核对和签发。 |
| `metadata_sha256` | 将 ① 当前旧 `SystemRecord` 传给 `ear_extraction.automatic_timeline.prewrite_run_metadata_sha256`。该函数只摘要旧任务身份、修订、时间、命令范围／种类、终态和有序调用 intent 等元数据；不摘要正文。 |
| `proof` | `"all_calls_saved_success_no_business_write"`，表示已独立核实整笔旧任务，无保留疑点。 |
| `calls` | 一项对应一个旧 intent，完全同序。每项只含 `call_id`、`record_saved: true`、`status: "success"`、`error_code: null`、`response_recoverable: false`。只能从已核实的持久审计投影，不可由 `returned` intent 补造。 |

- 上限为 64 个不同旧 run、合计 120 次已核实调用（仍受原配置 64 KiB 上限）。已列 pin 必须全部与相交的旧记录精确匹配；没有 pin、混入别的 run、缺调用、重复调用、不一致或过期均不放行。排序后的 pins 参与范围 SHA-256；加、删、改 pin 之后，已排队旧反馈不能继承授权，须用新反馈。
- 仅接受比新反馈早、单次尝试且可追溯的手动旧任务（非空范围只接受原 `extract`，不接受原 `reextract` 或自动时间线任务），全部 intent 都确实为 `returned`，并且符合既有 Course 的明确本地写入前错误；另允许仅划分调用的 `blocked` / `session_all_rows_unclassified`。没有 Course 的 `sending` 例外。`sending`、仍排队／在途、未知 Gateway 或 Storage 提交、以及返回了可用结果但未提交的旧任务一概不放行，不改写旧任务。
- worker 在读取新转写前重核旧任务元数据和有序 ID，首发及每个后续新调用前再次检查重叠任务与现行家族，提交前再核一次。非空范围另核精确的公开预览；旧活动及有效产物的每一条引文都须保留在新活动的证据中。提交沿用家族对象 CAS，并以动作集合修订防护最后一次保护核对后的竞态。旧审计不会进入新模型请求；新反馈和每次新调用均有新 ID，仅处理所选组件。依赖既有 ④ 单宿主写者假设；不保证不同宿主绕过锁时的全局互斥。已完成的旧 `extract` 不能使用失败证明。下面的专用旧成功证明仍拒绝同范围、自动或未核清任务。

## 可选：旧成功产物全部在本组件外

只给严格位于一个更大旧手动 `extract` 内的精确空组件使用 `proof: "all_calls_saved_success_outputs_only_outside_scope"`。整笔旧调用都已返回且保存成功；独立核对原来同次原子提交中所有活动版本，`outside_activity_ids` 列出原始有效 v1 的结果（允许它们已在范围之外整体替代，读取不可变 v1 复核），旧结果全在新范围外。还要独立核对包含已终止对象的全部版本历史及修订，固定 `scope_history`（每个 `activity`、`artifact`、`rule_selection` 分别填 `revision` 和 `versions`）。worker 读取历史再次核对（顶层最多 6,000 对象、历史额外版本最多 240），拒绝当前或过去任何活动及关联对象与该范围相交；后续发送和提交前重核修订。一旦其中一个版本变了，需重新审核新组件，不能用旧 pin。不会重放或改写旧成功请求。

## 可选：原 v1 自动划分失败后的一次 v2 试验

此例外默认关闭，不是旧反馈重试或全历史重跑入口。每个精确组件最多配置一个 `proof: "legacy_window_review_all_saved_success_no_business_write"`，放在同一个 `transcript_automatic_timeline_prewrite_pins` 私有数组中。其余字段与上面的表一致：`run_id`、`scope`、`metadata_sha256`、`calls`。`scope` 现在必须同时等于旧自动任务的完整命令区间。不要把一般的写入前失败证明用在旧自动任务上。

1. **独立核实并获明确授权**：确认旧任务是一次手动 `extract` 或 `reextract`，终态准确为 `blocked` / `automatic_timeline_invalid_window_review`；所有持久 intent 都是 `returned` 且用途**仅**为 `timeline_window_review`，没有生成、合并或其他调用。对照每个确切 call ID、用途和请求指纹，从已持久化的⑦审计逐个确认 `success`、已保存、无错误且不可恢复回复；也要独立确认该旧任务没有任何业务写入（含历史版本）。无须也不得取回回复。不能把 `returned` 或失败标签本身当证明，不能用 `reconcile` 补写 pending 审计来签发，缺任何一项则保持阻塞。宿主不自行证明负面写入事实。
2. **钉住原配置**：使用 `prewrite_run_metadata_sha256` 摘要当前旧运行，按原顺序列出所有已核实的调用。恢复原预检、原完整允许窗、原固定规则 ID，以及当时就已存在的其他空目标 pins（如有）；程序从这些信息重建 v1 范围指纹，必须等于旧运行保存的值。若原配置无法还原、边界或任何原 pin 已变、保护有疑点，停止。空目标仍走手动 `extract` 且不能有现行/已终止旧对象；非空仍走手动 `reextract`，此试验不混用写入前失败证明，公开 `preview.versions` 必须与旧尝试及当前版本完全相符，所有原有旧家族和保护校验仍适用。
3. **只开一个新反馈**：沿用同一范围和相同命令类型，等待本次明确终态；不重新提交旧反馈、不调用旧请求或复用旧 call ID。进入 v2 发送时在持久 `extraction_run` 中随发送 intent 记录 `automatic_timeline_v1_predecessor_run_id`。后续同一旧任务不能再次授权试验，包括 v2 也无效、返回未知或配置被移除再恢复；同一反馈重投不会续发。新的 `timeline_window_review_v2` 不可作为这个证明的前序。核对完后移除新增证明，不改写任何前序运行。仍依赖原来的单宿主锁；不新增凭据、审计访问或外部路由。

## 实现及边界

- `automatic_timeline.py` 用实际采集的 UTC 边界规划、用允许窗按范围读转写（不读录音/新权限、不打开广域快照），保留跨相接窗一行的完整原始时界。空窗、空白、零长、越界、无可靠划分均不向课时分块回退。逐窗只把局部序号、真实起止、剪裁标志和可见摘录经现有 `DurableCalls` 送 ⑦；无真实记录 ID 或原始路径（逐字稿里已有的内容不去标识）。托管 v2 使用新用途 `timeline_window_review_v2`。每个视图绑定单个调用：④先持久化该 call ID 及带视图的请求指纹，⑦客户端验证 HTTP 成功信封的 call ID 与已保存状态，再在本地检查该视图的回复。模型不收不回窗口摘要，也不回抄首末行引文。回复只含有序 `spans`：首末行必须在视图内、不重叠；参与证明、换场和接续仍按行号检查原样可见短引文（最多 64 字符），接续仍受双侧距离和时间约束。收到已保存且调用 ID 匹配的成功信封后，先原样校验闭合 v2 结构与全部 spans 的范围／顺序，才检查证明；不改 wire 或补造引文。全部视图检查后才组装和生成；离线 `plan/assemble` 仍按照原本的摘要、首末锚点及严格证明校验。结构校验不能证明模型的语义判断正确。
- 只把无结构冲突、无时间交叠的 `participation` / `watching_listening` 候选物化。通用标题区分参与和观看／收听；固定规则笔记只看到活动实际关联的完整转写，不收到未分类行、旧对象、边界审阅回复或额外身份字段。结果只保存有界计数、范围指纹和持久调用意图，不在任务审计保存转写／引文／回复。此路径不改变留存策略；宿主须保持⑦无正文留存、① `EAR_MODEL_BODY_ENABLED=false`。本地 wire 结构或范围／顺序错误仍阻塞为 `automatic_timeline_invalid_window_review`，`detail.automatic_timeline_review_failure` 只记录用途、从 1 开始的窗序号与 `reply_schema` 或 `span_bounds_or_order`。没有模型摘要错配类别。Gateway 没有给出匹配且确认为已保存的成功信封（含非 200、传输错误或 call ID 错配）时仍按 `gateway_outcome_unknown` 处理，而不是已返回的本地校验失败。
- 接续组装和正面参与校验后、旧对象后继与不确定范围检查前过滤短活动；其行仍是原始证据。`detail.below_min_duration_candidates` / `below_min_duration_rows` 仅在发生过滤时记录，并计入未物化候选和未归属行。若旧家族因此不满足替代条件，阻塞并保留这些计数。无可用活动时既有阻塞及不自动重发语义不变。
- v2 降级只丢弃未通过局部校验的证明：坏换场提示不产生切分，与同边的接续或切分主张相遇时标不安全；无效接续（包括同一边的重复证明）所指的可定位边界保持未决，不被重叠视图补成接续；坏角色证明清空引文并标 `unknown`，重叠视图的已知角色不能覆盖降级。组装时保留这些否定约束，写入前用它们拒绝触及旧活动时间（包含被降级边界两侧之间的时段）的整家族替代。只要任一窗发生降级，还须保留旧活动及其有效产物的全部引文，即使原本只检查后继。成功或无可落库活动时 `detail.review_proof_degradation` 只记三类计数，不记行号或引文。既有调用计划、预算和前序资格不改变：继续的只是原有待审窗口及合格候选的生成，不重发本窗，不为降级发补问，不新增重试或 v1 前序资格。
- 窗审阅按[模块入口](../README.md#宿主可选有界自动时间线划分transcript_automatic_timeline)配置分批。协调线程独占 Storage／上下文／运行修订：逐笔执行原有发送前守护、检查调用和字节预算、CAS 持久化意图、复核租约后才把请求交给线程池。池线程只调 `GatewayClient.complete`（锁定版本的同步 `httpx.Client` 可跨线程共享）；没有线程安全保证的注入端口仍串行。每批按窗口顺序逐个 CAS 记录已验证返回，再按该顺序校验／归并；结构失败可阻止后续批次，不能撤销同批已派发请求。不从回复中取窗口身份，也不记请求／回复正文。
- 未知结果与交付线程池使用同一个交接锁：一旦发布未知，不再派发，即使某个未交付的 `sending` 意图已经落库。已交付的请求继续收尾；持久化出错时不再派发，也不再用无确认的运行修订写回执。恢复检查**全部**意图：前面有 `sending` 即使末次 `returned` 也保持未知，整笔保留，不尝试恢复正文或重发。自动审计核对仍是尽力而为；`reconcile_run(run_id, call_id=...)` 可单独核对属于本运行的其他意图，默认优先核对最后一个 `sending`。核对只返回审计元数据，不解除阻塞。并发不影响原有范围指纹、允许窗调用总数、全串行估算的保守租约或 256 KiB 单请求上限。
- 窗数、时长、请求、总调用、租约和持久化上限沿用课堂宿主（1–24 个允许窗，各 ≤15 分钟，每窗 5 次总预算，最多 120 次）；另限 6,000 个转写查询结果（跨窗重复也计入）、48 个可落库活动、20,000 条重复登记的划分依赖边。留出固定规则生成的最低调用预算，否则停止；长笔记的生成／归并仍使用同一严格发送限额。不能靠超限截断后把剩余部分当作成功。
- 发送前检查整个组件的重叠运行（默认不放行；只接受上述显式、适用的证明）、最新版旧家族、公开预览及固定规则。逐窗读后留存原始类型修订及记录数；提交前重读旧家族/保护及重叠运行，重核 scoped 行数与原始修订。活动、受保护检查后的终止版本、新产物与规则选择、依赖及成功记录同批提交。集合检查依赖既有单宿主前提，规则和原始修订、旧目标版本和运行版本由 ① 拒绝冲突。已持久化发送意图的失败不自动重算、扩大窗口或回落旧算法；Gateway 审计仍只能核对结果状态，不能恢复回复。

## 合成回归

`UV_OFFLINE=1 uv run --no-sync pytest -q tests/test_mvp_worker.py -k automatic_timeline` 使用真实 worker 接线、测试 Gateway schema 验证及内存 Storage。覆盖物理与计算接缝、稀疏参与分类、v2 调用 ID、闭合结构与引文错误、重叠/未知调用、空组件、版本变化、缺后继、受保护动作、晚到转写、有界预算和同一个反馈的重投。`-k automatic_timeline_prewrite` 另外覆盖大范围前序的整笔审计、真实同进程 Course 空分类输出、私有 pin 失配、未知保持、历史对象和发送间／提交前竞争；`-k automatic_timeline_legacy_review` 覆盖仅在精确旧范围下试验、空目标和替代路径、旧用途/前序拒绝、持久一次性与保护检查。均为合成数据，不预测真实录音的边界质量。

## 计划：空目标组件的人工复核稿（未实现）

如果空目标组件也需直接复用人工标注，而非由本路径自动划分：为手动 `extract` 增加独立、互斥的私有草稿键，复用同一完整组件预检及空目标的发送前/提交前检查。草稿必须绑定完整转写指纹（含省略行）、精确允许窗和私有 spans，使用完整逐窗复核编译；不改现有 `ReviewedTimelineDraft` 要求有效旧活动的重提取边界。该子模式只经 ⑦ 生成固定规则笔记，不发送审核材料、不重新划分，也不允许由校验失败回落至自动模式。合成验收应覆盖没有旧家族时的精确写入、校验失败时零发送、途中出现旧对象时无提交，以及同范围的成功／未知运行阻止重放。
