# ④ 活动提取 MVP 设计

> 本文记录已恢复的初版 MVP（`f3c28db`），用于演示，不代表已完成当前 v1.2 设计。

## 1. 目标与边界

将一段时间内的录音转写、GPS 和手机信息整理成活动，根据用户规则生成 Markdown 笔记、待办及待审核的日历／提醒建议。人物归属纠正后，按⑤的请求重新判断相关产物。

| 对接模块 | ④使用的能力 |
|---|---|
| ① 存储与事件 | 读取证据、人物、地点和归属；保存结果、版本和依赖；接收事件 |
| ② 适配器 | 使用其已入库的原始数据，不重做音频处理 |
| ③ 归属 | 使用人物、地点和归属结果，不自行认人或维护参考 |
| ⑤ 依赖分析 | 接收指定产物的重判请求，不自行传播修改 |
| ⑥ API | 消费用户反馈，提供可查询的处理状态；外部动作由⑥执行 |
| ⑦ 大模型入口 | 活动划分、规则选择、提取和重判的统一调用入口 |

④只写活动、规则、产物、建议和提取记录，并为自己的产物登记依赖。MVP 通过 API 和脚本验收，④不建设用户界面。

## 2. 七个内部子模块

七个子模块放在同一个 extraction 服务中，不拆成独立服务。

| 子模块 | 功能 | 对应流程 |
|---|---|---|
| 调度执行 `orchestration` | 接收反馈、定时触发和重判请求；检查归属；管理任务、重试与恢复 | 流程入口与串联 |
| 活动划分 `segmentation` | 根据原始证据划分活动，校验时间边界；身份纠正不改变活动划分 | 时间段 → 活动 |
| 规则管理 `rules` | 规则增删改、适用性判断、只改本次、应用到历史活动 | 活动 → 适用规则 |
| 产物生成 `artifacts` | 生成 Markdown、校验引用；依据旧产物和修改原因重判 | 活动＋规则 → 产物 |
| 建议管理 `suggestions` | 生成动作建议、处理审核和执行回执、替代未审核旧建议 | 产物 → 建议及状态 |
| 结果提交 `persistence` | 通过①原子提交结果和依赖，处理版本冲突及去重 | 结果落库 |
| 模型调用 `model_io` | 管理提示词、结构化输出和校验，统一调用⑦ | 支撑模型处理步骤 |

## 3. 主流程

**首次提取**

```text
定时触发／手动提取反馈
  → 确定待处理时间范围
  → 检查声纹、GPS 是否已有归属
  → 划分活动 → 选择规则 → 生成 Markdown 产物
  → 规则带动作时生成建议
  → 保存结果、依赖和成功进度
```

- 定时提取从上次成功进度推进，并扣除所有已经成功处理的区间；失败不算成功覆盖。
- 缺归属时延后重试，超过等待上限后失败并提供原因。未命名人物、未知地点也是合法归属。
- 长数据分段处理并校验合并后的活动边界；超预算或输出无效时明确失败，不静默截断。
- 活动和产物使用 `[[person:<id>]]`、`[[place:<id>]]` 引用，由⑥显示当前名称。
- 每份产物依赖所属活动、采用的规则版本，以及活动时间范围内所有归属关系。

**归属变化后的重判**

```text
③修改归属 → ⑤查依赖并发请求
  → ④读取原规则、旧产物和修改原因
  → 内容不变：保留原文，刷新依赖
  → 内容改变：保存新版本，替代未审核旧建议并重新生成
```

④不直接监听归属变化来启动提取。重判不重新划分活动，不自动改用最新规则；已通过、已执行、已拒绝的建议保留。

## 4. 用户操作

所有操作先由⑥保存为反馈，再由④处理。

| 操作 | ④的处理 |
|---|---|
| 新增、修改、删除规则 | 保存规则变更，只影响以后，不自动重做历史 |
| 只改这一次 | 创建绑定某活动的规则，立即提取并追加产物 |
| 应用规则到历史活动 | 跳过选规则，按指定规则提取并追加产物 |
| 重新提取一段时间 | 提供影响范围及用户修改数量；确认后重新划分，替代旧活动和产物，新活动使用新 ID |
| 审核建议 | 更新为通过或拒绝；通过后由⑥执行 |
| 外部执行回执 | 更新执行成功或失败状态；重复回执不重复处理 |

重新提取先准备新结果，再提交旧结果替代，避免失败后丢失已有结果。跨越所选时间边界的旧活动须明确影响范围，不静默覆盖范围外内容。

## 5. 数据与可靠性

| 数据类型 | 关键内容 |
|---|---|
| `activity` | 时间范围、名称、描述、来源证据 |
| `rule` | 适用范围、提取要求、可选动作、活动限定及版本 |
| `artifact` | 所属活动、规则及版本、Markdown 正文、证据引用 |
| `action_suggestion` | 来源产物及版本、日历／提醒参数、审核与执行状态 |
| `extraction_run` | 触发来源、处理区间、状态、输入快照、错误及模型调用记录 |

复用①的公共字段和存储接口。结果、依赖与成功进度原子提交；重复事件只生效一次；版本冲突后重新读取并判断。运行状态保存后才能确认接单，恢复时继续未完成工作。

模型调用带 `module=extraction`、`root_feedback_id` 和运行 ID。输出中的时间、人物、地点和证据引用必须校验；时间不明确时不编造可执行日历／提醒参数。
